> 本文档梳理全栈（后端 FastAPI + 前端 Vue3/Three.js）的**业务逻辑**与**数据逻辑**，

## 2. 业务逻辑（做什么）

### 2.1 核心业务域：钢铁长/短流程减碳仿真

| 业务域 | 说明 | 主流程 |
|---|---|---|
| **工艺仿真** | 用户配置工序参数（产量/焦比/电耗等）→ 后端计算每工序碳排/能耗/成本 | `simulate(model, ops, factors)` → `carbon_engine.run()` |
| **流程编排** | 拖拽编排工艺节点、连接物料流、绑定可调设备 → 编译为仿真 model | `compileSchemeToModel()`（前端） |
| **策略管理** | 自然语言描述优化策略 → 解析为参数指令 → 应用/对比/保存 | `parse() → api.applyParsed → applyStrategy` |
| **实时监测** | WebSocket 推送设备实时数据（模拟/自定义源），驱动 3D 状态与 KPI | `realtime.py` + `api.openFeed()` |
| **报告生成** | 生成仿真/策略分析报告（Markdown → HTML 下载） | `main.py /api/report/...` |

### 2.2 核心算法：碳排放核算（calculators.py + carbon_engine.py）

- **注册表模式**：`calculate()` 按 `unit.type` 分发到对应工序计算器（高炉/转炉/电炉/精炼…），
  未知类型返回 `(0,0,0)` 兜底，新增工序只需加一个实现类。
- **能量守恒**：多数工序按 `燃料/电力消耗 × 因子` 折算，铁水/钢水环节计入物料碳转移与固碳。
- **汇总**：`carbon_engine.run()` 聚合全部工序 → `totals`（能耗/碳排放/成本/单位产品碳）→ 缓存。

### 2.3 仿真缓存（carbon_engine.cached_simulate）

- 键 = `(model, ops, factors)` 序列化；命中直接返回，避免重复计算。
- 前端另有 **280ms 防抖刷新 + 过期响应序号丢弃**（sim.js `_runRefresh`），双重防抖保跟手。

## 3. 数据逻辑（数据结构与数据流）

### 3.1 核心数据结构

```
SimModel（仿真模型）
  units[]: { id, type, name, x, z, rot, params{}, techs[], enabled }
  flows[]: { id, from_unit, to_unit, material, rate }
  spec: 工艺规格档位（如高炉 3200m³）

Factors（排放因子输入）
  能源碳含量 / 电力碳因子 / 水耗折算 / 各工序单位能耗基准 …

Params（工序参数，与 param_schema / EDITABLE_PARAMS 对齐）
  blast_furnace: { hot_metal, coke_rate, coal_inj, flux, wind_rate, … }

Scheme（编排方案，仅编辑态使用）
  nodes[] / connections[] / devices[] / groups[]
  → 由 compileSchemeToModel() 编译为 SimModel
```

### 3.2 前端数据流（stores/sim.js 单例 store）

```
用户操作 → action（setUnitParam / refresh / parse …）
  → 本地即时更新（跟手） → refresh() 280ms 防抖
  → api.simulate() → baseline 更新 → _pushModelToFeed()
  → getters（schemeTotals / unitEmissions …）→ 组件响应式渲染
```

- **业务静态数据已抽离**：`EDITABLE_PARAMS / UNIT_TYPES / CATEGORY_ORDER / TECHS / OP_PARAM_KEYS / DIRECT_PARAM_KEYS`
  位于 `data/processMeta.js`，`sim.js` 仅 re-export 保持组件兼容 → **业务数据与代码逻辑分离**。

### 3.3 后端数据流

```
GET /api/param-schema ──→ platform_config.apply_to_schema()（叠加配置后深拷贝返回）
POST /api/simulate   ──→ cached_simulate → carbon_engine.run() → calculators[type].calculate()
POST /api/parse      ──→ nl_parser.parse()（本地规则）→ llm_strategy（LLM 补充/降级）
WS   /ws/feed        ──→ realtime.py：缓存模型 + 300ms 合并快照推送
策略持久化             ──→ store.py（JSON 文件）· report_store.py（报告 JSON）
```

## 4. 模块职责速查（后端）

| 模块 | 职责 | 关键依赖 |
|---|---|---|
| `main.py` | 路由 + WS + 后台报告任务（锁 + dict 轮询状态） | 其余全部 |
| `carbon_engine.py` | 仿真编排 + LRU 缓存 + totals 汇总 | calculators, factors, models |
| `calculators.py` | 工序碳/能耗计算器注册表 | factors |
| `factors.py` | 因子查表（无外部依赖，最底层） | - |
| `realtime.py` | WS 推送（FeedCache + 快照） | store |
| `report.py / report_store.py / md_render.py` | 报告三件套 | carbon_engine, nl_parser |
| `platform_config.py` | 平台可配置项合并/持久化 | param_schema, devices, specs |
| `nl_parser.py / llm_strategy.py` | 自然语言策略解析 | param_schema |
| `store.py / presets.py / specs.py` | 策略/预设/规格数据 | models |
| `models.py` | Pydantic 校验模型 | - |

## 6. 维护注意事项

- 新增工序参数 → 同步维护 `data/processMeta.js`（前端编辑元数据）与 `param_schema.py`（后端 schema）。
- 新增设备类型 → `devices.py`（元数据+规格）+ `three/builders/`（3D 构件）。
- 仿真公式变更 → 只改 `calculators.py` 对应工序实现，注册表自动分发。
- 策略解析规则 → `nl_parser.py`；需要 LLM 补全时走 `llm_strategy.py`。

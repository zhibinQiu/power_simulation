## 0 装置、传热链与控制目标

### 0.1 硬件前提（实测，一体机 nt001）

- 制冷片电源 `zhileng-power`（485 从站 1）与风扇电源 `fengshan-power`（485 从站 4）同为 24V/5A 数控电源，共用 `/dev/ttyRS485`、9600-8N1；
- 温度通道均为 LoRa 终端，**更新周期约 15s、随机抖动 0~15s、存在丢包**（`env-temp` 应答率最低，age 可达数分钟）；
- 执行器（电流/电压）**存在约 8s 建立时间**，并非理想无动态；
- 采样周期统一取 **$T_s=15$s**（取值依据见 §5.1）。

### 0.2 温度通道的分工

| 通道 | 角色 | 说明 |
| --- | --- | --- |
| `servers-temp` | **被控量 CV，也是 ESO 唯一的测量** | 水温 |
| `shuitong-temp` | 可测扰动 $m_k$ 之一 | 热端冷却水温度，同时作为 $T_{hot}$ 参与 $\Delta T$ |
| `env-temp` | 可测扰动 $m_k$ 之一 | 环境室温；**同时是路径②（仅风扇制冷）的驱动温差来源**——水温被拉向湿球温度 $T_{wb}\le$ 干球温度，无湿度测点时用它作保守代理 |
| `zhileng-temp` | **仅离线诊断，不进入控制模型** | 冷端风口温度 |

`zhileng-temp` 不纳入模型的理由：它既不是被控量，也不是安全约束对象。纳入会把辨识从单输出变成多输出，并要多标定一路探头时间常数，工程复杂度上升而收益不明确。该通道仍写入 CSV，可用于离线诊断（例如验证制冷量随电流的非单调性、检查冷端是否异常），但不参与在线闭环。

由此确定的架构：**水温是唯一的被控量，也是 ESO 唯一的测量通道**，即单输出（SISO）架构。

### 0.3 传热链（本方案的结构核心）

```
路径①（串联）：TEC 冷端 ─► 冷端散热器 ─►【风扇驱动的气流】─► 杯子/水体
路径②（独立）：环境空气 ─────────►【风扇驱动的气流】────► 杯子/水体（含水面蒸发）
热端：          TEC 热端 ─► 冷却水带走热量（shuitong-temp）
```

这条链给出三条**结构**事实（详见 §2.1，本文档只取结构信息，不用物理机理建模）：

1. **路径①上 $u_1$（TEC 电流）与 $u_2$（风扇电压）是串联耦合，不是可加的独立通道**。TEC 的冷量必须先产生、再靠风送出去，$(u_1,0)$ 组合下制冷量为零、TEC 白耗电；
2. **$u_2$ 自身还是一条独立的制冷路径②**——**只开风扇也能把水杯降温**（强迫对流 + 开放水面蒸发），能力随风量单调上升、边际递减，但有物理下限：水温只能被拉到环境湿球温度 $T_{wb}$，压不到 $T_{wb}$ 以下；
3. **热端由冷却水散热，与风扇无关**。因此风扇不参与热端散热。

### 0.4 控制目标

在满足 $T_{\min}\le y_{true}\le T_{\max}$ 的前提下，**最小化 TEC + 风扇的总电功耗**。这是一个经济优化问题（目标函数不是"跟踪误差最小"），因此采用 EMPC 而非常规跟踪 MPC。

> **⚠ 目标函数必须与考核口径一致（见 §11）**
>
> 本方案的"经济性"只有在**考核指标同时包含温度与能耗**时才成立。若考核只看某一时刻的温度（如"45 min 时刻水温不得高于规则基线"），纯经济目标会主动把水温顶到 $T_{\max}$ 附近以省电，终端温度必然劣于基线——**这不是算法失败，而是目标函数与考核指标不一致**。§11.4 给出处理办法：把考核温度转成**约束**，把能耗留在**目标**里，二者不可颠倒。

## 2 系统数学模型

### 2.1 装置结构与输入-输出拓扑

控制问题的骨架由**结构**决定，而结构是可直接观察、且**可迁移**的信息。装置的传热路径为：

```
路径①（串联）：TEC 冷端 ─► 冷端散热器 ─►【风扇驱动的气流】─► 杯子/水体
路径②（独立）：环境空气 ─────────►【风扇驱动的气流】────► 杯子/水体（含水面蒸发）
热端：          TEC 热端 ─► 冷却水带走热量（shuitong-temp）
```

由此得到三条结构事实：

1. **路径①上 $u_1$ 与 $u_2$ 是串联关系，不是可加的独立通道**——TEC 冷量必须先产生、再靠风送出去；
2. **$u_2$ 自身还构成路径②这条独立制冷通道**——**只开风扇也能把水杯降温**，极限是环境湿球温度 $T_{wb}$；
3. **热端由冷却水散热，与风扇无关**——风扇不参与热端散热。

**由结构可直接推出的两个退化极限**（不需要任何物理公式）：

- **$u_2\approx0$（风扇不转）**：路径①断（TEC 冷量送不出去）、路径②也只剩自然对流，被控量**几乎不响应** $u_1$；而 TEC 仍在耗电 → **纯浪费电**。注意此时是**两条路径同时失效**，所以"风扇停转"等价于制冷能力归零（§6.1）；
- **$u_1=0$**：**不是"不产生制冷能力"**——风扇仍在把水温往 $T_{wb}$ 拉，只是该通道**有下限**：水温降到 $T_{wb}$ 附近后风量再大也无用，要继续往下压才必须投入 TEC。

> **⚠ 已修正的错误（本方案原稿写错、后果最严重的一处）**
>
> 原稿在此处写「$u_1=0$ 时 $u_2$ 只是把环境空气吹过被控对象，不产生制冷能力」，等价于假设 $Q_{net}(0,u_2)=0$。**这是错的：只开风扇同样能给水杯降温**——气流掠过水面带来强迫对流换热，开放水面还额外蒸发吸热，水温被持续拉向湿球温度（可低于室温）。
>
> 后果不是"模型差一点"，而是**系统性选错最优点**：风扇功耗通常比 TEC 低一个数量级，而它自带的制冷能力是免费搭送的。只要 $T_{\max}>T_{wb}$，最省电的解往往就是「大风量 + 零/小电流」。若模型抹掉这条通道，EMPC 会低估 $u_2$、偏向多开 TEC——**闭环照样很稳，电费却白白高出一截**，与 §5.3 强调的"功耗模型错了是系统性地选错最优点"是同一类错误，只是这次错在**制冷侧拓扑**。

这些是**拓扑结论**，因此可迁移：机房里「冷水阀开度 / 风机转速」是完全相同的结构——风机既把盘管冷量送到机柜（路径①），本身也强化机柜与回风/环境的换热（路径②，室外低温时即**免费制冷 free cooling**）（见 §10）。

> **本文档的建模立场**
>
> 除上述拓扑信息外，**不引入任何物理机理公式**。所有函数形式——功耗模型 $P_{tec}(\cdot)$、$f_{fan}(\cdot)$、对象阶次 $n_p$、扰动通道——一律视为**待选的候选结构**，由 §5.3 / §5.5 的数据经模型竞争确定。
>
> 理由：半导体制冷与受迫对流换热的机理是本装置特有的，一旦换到机房 CRAC（压缩机 + 制冷剂相变）就全部失效；而「先做实验、再由数据选结构」的流程是与物理无关的，可以直接迁移。

### 2.2 两个输入的经验特性：四条待检验命题

以下四条**既不是建模依据，也不进入模型结构**，只用于**设计实验**和**检查结果是否合理**。每条都必须由实测数据检验，检验结果决定工作区与模型形式。

| # | 经验命题（待检验） | 检验方式 | 检验为真时的处置 |
| --- | --- | --- | --- |
| 1 | 制冷量对 $u_1$ **可能非单调**——电流过大时制冷效果反而变差，存在最大值点 | §5.2 联合阶跃：各 $u_2$ 档位下扫 $u_1$，看稳态降温幅度是否随电流增大而回落 | 把 $u_{1,\max}$ 压到转折点以下，或改用分段线性 / 增益调度 |
| 2 | 存在**内点经济最优**——不是"动作越小越省电" | §5.3 网格：检查相同制冷效果下不同 $(u_1,u_2)$ 组合的功耗是否有显著差异 | 有内点最优 → EMPC 有意义；若功耗对组合不敏感 → 退化为普通跟踪 MPC 即可 |
| 3 | $u_2$ 的**边际制冷收益递减**——风量加大到一定程度后收益变小 | §5.2 联合阶跃 + **纯风扇阶跃** + §5.3 网格：看降温幅度对 $u_2$ 的斜率是否随 $u_2$ 减小 | 结合风扇功耗随 $u_2$ 递增，核定经济最优风量，避免运行在无效的大风量区 |
| 4 | **仅风扇即可制冷，且其能效比（W 制冷 / W 电耗）远高于 TEC**——存在「先风扇、后 TEC」的投入优先级 | §5.2 的**纯风扇阶跃**（$u_1=0$ 扫 $u_2$）：量出稳态水温能降到多少、离 $T_{wb}$ 还差多少；再与 §5.3 功耗数据合并，对比"同等降温幅度"下风扇与 TEC 的电耗 | 若仅风扇即可满足 $T_{\max}$，常态解应为**大风量 + 零/小电流**，TEC 退化为"只在需要低于 $T_{wb}$ 时才投入"的增量手段；此时 $u_{2,\max}$ 成为首要经济杠杆。**禁止**把这种情况判成"TEC 通道异常" |

**为什么把物理直觉放在这里而不是模型里**：这四条在多数对流换热系统中成立，但换成机房后具体的数值与转折点全变，唯一不变的是**"要检验这四件事"**。把它们写成待检验命题、由数据判定，就把不可迁移的物理知识换成了可迁移的实验流程。

### 2.3 串联耦合（路径①）与独立通道（路径②）的数学形式与后果

把实际从水体取走的净制冷量记为**形式未知**的多元函数 $Q_{net}(u_1,u_2;y_{true})$——**不预设它是乘积、可加或任何特定形式**。§2.1 的结构只给它**一条硬约束 + 一条饱和性质**：

$$
Q_{net}(u_1,0;\cdot)=0 \qquad\text{（风扇不转：路径①断）}
$$

$$
Q_{net}(0,u_2;y)=Q_{fan}(u_2;y)>0,\quad u_2>0,\ y>T_{wb};\qquad Q_{fan}\ \text{随风量递增、边际递减}
$$

> **⚠ 已修正**：此处原写 $Q_{net}(0,u_2)=0$，即"任一输入为零时净制冷量恒为零"。**该式对 $u_2$ 不成立**——只开风扇会吹环境空气掠过水面，靠强迫对流与蒸发把水温拉向湿球温度，制冷量显著大于零（§2.1 修正说明）。
>
> $u_2=0$ 时制冷为零的真正原因是**路径①与路径②同时断**（无风送冷、也无风换热），不是"风扇自己不制冷"。

剩下那条零约束 $Q_{net}(u_1,0;\cdot)=0$ 已足以否定"可加"形式：若 $Q=f(u_1)+g(u_2)$，则由 $Q(u_1,0)\equiv0$ 逼出 $f$ 为常数，即 $Q$ 与 $u_1$ 无关——与事实矛盾。因此两个输入**仍然不是可加的独立通道**，只是不可加的原因现在有两条（路径①串联 + 路径②随状态饱和）。

**为什么线性模型的可加性只是局部近似**

对未知的 $Q_{net}$ 在标称点 $(u_1^0,u_2^0,y^0)$ 做 Taylor 展开：

$$
Q_{net}\approx Q_0+g_1\Delta u_1+g_2\Delta u_2+g_y\Delta y
+\underbrace{\frac{\partial^2Q}{\partial u_1\partial u_2}}_{g_{12}}\Delta u_1\Delta u_2
+\underbrace{\frac{\partial^2Q}{\partial u_2\partial y}}_{g_{2y}}\Delta u_2\Delta y+\cdots
$$

两个交叉偏导**一般都不为零**：$g_{12}$ 来自路径①的串联耦合，$g_{2y}$ 来自路径②的"换热系数 × 温差"（风量越大，水温向 $T_{wb}$ 回归越快）。这意味着：

1. 一阶（线性可加）模型只在 $(u_1^0,u_2^0,y^0)$ 的**足够小邻域**内成立。$g_1$ 是 $u_2$ 的函数（风越大、同样电流的制冷效果越强），$g_2$ 是 $u_1$ 与 $y$ 的函数。**离开标称点外推必然产生系统性偏差**；
2. **不能在固定一个输入的条件下单独扫另一个来求"通道增益"**——那样得到的 $B_p$ 列只在该固定值下成立。§5.5 的双输入联合激励因此是**硬性要求**；
3. **$u_2$ 不只进 $B_p$，还会改变 $A_p$**：路径②的换热量正比于 $(y-T_{wb})$，并入对象动态后，$u_2$ 实际在改变"水温向环境回归的时间常数"。线性化时这一项一部分落进 $A_p$、一部分落进 $B_p$ 第二列——**两者都是工作点的函数**。这比 §2.8 提到的"风扇惯性串入"更本质，是 §2.9 必须限制工作区的又一理由；
4. 反过来，这也正是 EMPC 的价值所在：满足同一制冷需求有无数组 $(u_1,u_2)$ 组合（大电流小风量 vs 小电流大风量 vs **纯大风量**），功耗差异显著——经济优化就是在耦合约束下挑最省电的那一组。

**关于功耗侧**：串联耦合只存在于制冷通道的**路径①**；路径②是 $u_2$ 的独立通道，但它只增加制冷、不增加耦合。而 $u_1$ 与 $u_2$ 由**两个彼此独立的控制电源**供电，各自的总功耗只由自身决定，因此**总功耗严格可加**：

$$
P_k \;=\; P_{tec}\big(u_{1,k};\ \Delta T_k\big) \;+\; P_{fan}\big(u_{2,k}\big)
$$

式中 $\Delta T_k$ 不是独立输入，而是被控量 $y_{true}$ 的函数（§2.7）；冻结 $\Delta T$ 后 $P_{tec}$ 退化为纯 $u_1$ 的函数。

**功耗侧不存在 $u_1u_2$ 交叉项**——这是电源拓扑给出的结论，不是拟合假设，也不是物理机理推导。

> **必须区分两条耦合路径**（容易混淆）：
>
> | 路径 | 是否存在 | 说明 |
> | --- | --- | --- |
> | **直接交叉项** $u_1u_2$ | **不存在** | 两电源独立，互不牵连 |
> | **间接耦合** $u_2\to y_{true}\to\Delta T\to P_{tec}$ | **存在** | $u_2$ 改变水温，水温进入 $\Delta T$ 后影响 $P_{tec}$ |
>
> 关键是：**间接耦合已被 $\Delta T$ 项显式表达，不需要再额外添加 $u_1u_2$ 项**；而且 §2.7 的「冻结 $\Delta T$」会在预测时域内把这条路径一并切断，使 $P_{tec}$ 退化为纯 $u_1$ 的函数。
>
> 因此 MPC 目标函数里 **$P$ 对两个输入严格可加、各自凸**，凸 QP 结构不受串级耦合影响——这也解释了为什么制冷通道的耦合不影响优化问题的凸性。

### 2.4 热对象线性状态空间模型

在标称工作点邻域内，用黑盒数据驱动模型描述热对象：

$$
\begin{cases}
\boldsymbol{x}_{p,k+1} = A_p \boldsymbol{x}_{p,k} + B_p \begin{bmatrix}u_{1,k}\\u_{2,k}\end{bmatrix} + B_m m_k + B_d d_k \\[6pt]
y_{true,k} = C_p \boldsymbol{x}_{p,k}
\end{cases}
$$

- 全部热惯性（水体、散热器、风道）由 $A_p$ 刻画，纯数据驱动，不依赖任何传热物理公式；
- $B_p$ 的两列即 §2.3 中的局部增益 $g_1,g_2$，**其值随标称工作点变化**；
- $B_m m_k$ 是**可测扰动前馈通道**：室温与冷却水温度是已经能测到的扰动，把它们显式建模为前馈，而不是全部塞给不可测的 $d_k$，可显著改善室温漂移工况下的表现。辨识时作为额外输入列参与即可。

### 2.5 等效热负载扰动模型

$$
d_{k+1}=d_k
$$

**为什么把扰动建成积分环节（常值模型）**

把不可测热负载 $d$ 扩成状态、并令其"不变"，是 ESO 处理未知扰动的标准做法，其发挥作用依赖内模原理：

- 若真实扰动是**阶跃突变**（场景 A：突然出现热源），常值模型在稳态下与之完全匹配，观测器可以做到**无静差估计**——$d_{k+1}=d_k$ 提供的正是阶跃信号的内模；
- 若真实扰动是**缓慢漂移**（场景 B：室温渐变），常值模型并不严格匹配，但在 Kalman 框架下给 $d$ 分配一个小的过程噪声 $Q_d>0$，模型实际退化为**随机游走**，即可平滑跟随。

因此"$d_{k+1}=d_k$"与"用 $Q_d>0$ 做 Kalman"是配套使用的：前者给突变提供无差保证，后者给慢漂移提供跟随能力。$Q_d$ 越大，$\hat d_k$ 跟得越快、但对测量噪声越敏感。

**$B_d$ 是设计量，不是辨识量**

$d_k$ 不可测量，任何辨识算法都无法从数据给出 $B_d$（它对输入-输出数据的影响与 $B_p$ 的列线性相关，不唯一）。工程取法：

- 默认 $B_d=B_p[:,0]$（把扰动等效为 TEC 通道的输入偏置）；
- 若扰动主要来自热端侧，取 $B_d=B_p[:,1]$；
- 或 $B_d=B_p w,\ w\succeq0,\ \lVert w\rVert_1=1$ 按先验分配。

**可观测性警告与缓解**

热对象主导时间常数数百秒，$T_s=15$s 时 $A_p$ 的慢极点已接近 0.95~0.98，**本身已近似积分器**。再叠加一个积分扰动 $d$，两个几乎重合的慢模式会让可观测性矩阵条件数极差 → 观测增益巨大、测量噪声被严重放大。缓解手段：

1. 辨识时不要让 $A_p$ 去"吸收"一个近乎积分的模式（必要时先去趋势，把慢漂移交给 $d$）；
2. 用 Kalman 的 $Q_d$ 显式调节 $d$ 的跟踪速度，而不是一味提高整体观测器带宽；
3. **严格控制对象阶次 $n_p$**——单测量下每增一阶都在恶化可观测性，$n_p$ 以自由仿真误差不再改善为准，不要为了拟合指标盲目加阶；
4. 上线前数值检查 $\mathrm{cond}(\mathcal{O})$，超过 $10^6$ 需重新设计。**单测量架构下此项为强制检查**。

### 2.6 温度传感器一阶惯性滞后模型

$$
\begin{cases}
x_{s,k+1} = a_s x_{s,k} + b_s\, y_{true,k} \\[4pt]
y_{w,k} = x_{s,k}
\end{cases}
\qquad
a_s=e^{-T_s/\tau_s},\quad b_s=1-a_s
$$

**为什么必须显式建模探头动态**

探头读数 $y_w$ 滞后于真实水温 $y_{true}$。若不建模，这个滞后会被辨识算法误吸收进对象模型 $A_p$，导致：

- 模型预测的"当前温度"实际是几十秒前的温度，MPC 的约束判断系统性偏乐观；
- 与 ESO 的真实温度估计耦合时产生相位错误。

把探头动态单独建模为一个**已知极点**，ESO 就能从滞后读数中反推出真实温度——这正是"用带滞后的测量去观测不带滞后的状态"的标准处理方式。

**离散化口径必须统一**

上式为**零阶保持（ZOH）离散**，**不含直接项**（读数只依赖到 $k-1$ 时刻的真实温度）。§5.4 标定 $\tau_s$ 必须用同一口径；若改用 Tustin 离散会出现直接项，两种口径混用会使 $b_s$ 差一拍。

**为什么不能先逆滤波再辨识**

由上式可解出 $y_{true,k}=(y_{w,k+1}-a_s y_{w,k})/b_s$。看似能"还原真实温度"，实则不可用：

- $b_s\approx T_s/\tau_s$ 是个小量，除以 $b_s$ 把测量噪声**放大约 $\tau_s/T_s$ 倍**；
- 更严重的是，放大后的噪声与回归量（$y_w$）**相关**，使 ARX / 子空间估计产生**系统性偏差**，而不只是方差变大。

正确做法见 §5.5：直接辨识 $u\to y_w$ 的**整体**模型（含探头滞后），再按 §5.4 已知的探头极点**解耦**出 $A_p,C_p$。

**探头安装要求**：水温探头必须**完全浸没**。若有部分暴露在空气中，室温会经探头柄导热污染读数，等于给测量通道开一条未建模通路。先做物理隔离，再谈算法。

### 2.7 功耗模型

**TEC 功耗（形式由数据选定，不做物理推导）**

唯一的先验是：实测 5A/9.2V（约 46W）已明显超线性，故功耗对电流至少是二次以上的。把候选形式列出，由 §5.3 的网格数据经**测试集 RMSE + AIC** 竞争选优：

| 候选 | 形式 | 说明 |
| --- | --- | --- |
| T1 | $R u_1^2+S\,\Delta T\,u_1+P_0$ | 二次 + $\Delta T$ 线性耦合 + 常数 |
| T2 | $R u_1^2+P_0$ | 不含 $\Delta T$ |
| T3 | $a u_1+b$ | 纯线性（作为对照/下限） |
| T4 | $R u_1^3+P_0$ | 三次 |
| T5 | 分段线性 / 二维查表 | 非参数，拟合能力最强但无外推性 |

> **这些候选只是经验假设，不是物理推导**。$u_1^2$ 项不代表焦耳热，$\Delta T\,u_1$ 项也不代表塞贝克反电动势——它们只是拟合数据的候选基函数，选中哪个由数据说话。这样处理的好处是：换到机房 CRAC 后，只需换一批候选（压缩机功耗的特性完全不同），**选结构的流程本身不用改**。

下文以当前最可能入选的 T1 为例展开（若竞争结果不同，按选定形式相应重写 §4.1 的目标函数与 Hessian）：

$$
P_{tec,k} = R_{tec}\, u_{1,k}^2 \;+\; S_{tec}\, \Delta T_k\, u_{1,k}
$$

- **凸性要求（硬约束，优先级高于拟合精度）**：无论选中哪个候选，最终进入 $J$ 的 $P_{tec}$ 必须**关于 $u_1$ 凸**（$R_{tec}>0$）。这是 QP 结构的前提。若实测形非凸，改用其分段线性凸包逼近；
- **不含 $u_1u_2$ 交叉项**（§2.3）：两个输入由**独立控制电源**供电，总功耗严格可加，$P=P_{tec}(u_1)+P_{fan}(u_2)$。$u_2$ 对 $P_{tec}$ 的间接影响已由 $\Delta T$ 项承载，冻结 $\Delta T$ 后即消失。§5.3 会把交叉项作为**对照项**拟合一次以验证该假设（预期系数不显著）；若显著，说明存在共电源/共母线等**电气**耦合，那是硬件问题，应排查硬件而非改模型；
- $\Delta T$ 的实测口径：装置未装陶瓷面温度传感器，故用 **`shuitong_temp`（热端冷却水温度）− 水温** 近似 $\Delta T=T_{hot}-T_{cold}$。只要该近似与真实冷热端温差**单调线性相关**，比例误差会被 $S_{tec}$ 吸收，回归仍有效，但系数不可跨装置移植；
- **离线**（§5.3 扫描）用 `shuitong_temp − servers_temp` 测量值；**在线**用 `shuitong_temp − \hat y_{true,k}`（ESO 估计的真实水温）。

**风扇功耗（形由数据确定，禁止预设）**

$$
P_{fan,k}=f_{fan}(u_{2,k})
$$

候选形：$au_2^2$、$au_2^3$、$au_2+b$、带死区分段线性。按 §5.3 的测试集误差与 AIC 选优。无刷/PWM 风扇的 $P$-$V$ 关系介于线性与三次之间，没有理由预先假定某一形式。

**总功耗**：$P_k=P_{tec,k}+P_{fan,k}$

**MPC 内的凸近似：准静态冻结 $\Delta T$**

$\Delta T$ 依赖被控量 $y_{true}$，而 $y_{true}$ 在预测时域内由 $u$ 决定。若不处理，$P_{tec}$ 中会出现 $u_1\cdot y_{true}$ 的非线性耦合，QP 结构被破坏。

由于 $\Delta T$ 的变化速度比电流慢一个数量级（热惯性），在每个优化时域内**把它冻结为当前估计 $\widehat{\Delta T}_k$**：

$$
P_{tec,k+i\mid k}\approx R_{tec}\,u_{1,k+i}^2+\big(S_{tec}\widehat{\Delta T}_k\big)\,u_{1,k+i}
$$

这样 $P_{tec}$ 关于 $u_1$ 仍是**凸二次**（要求 $R_{tec}>0$），QP 结构不变；每拍用新的 $\widehat{\Delta T}_k$ 重新冻结一次，滚动修正。

**凸性保障（工程必做）**

- 强制 $R_{tec}>0$；若拟合为负（共线性/过拟合），改用 NNLS 重拟合，或对 Hessian 做 PSD 修正（特征值裁剪）；
- $f_{fan}$ 必须选**凸**形；若实测最佳形非凸（带死区的凹段），改用分段线性凸包逼近。

### 2.8 执行器动态与「优化变量 vs 模型输入」的一致性

模型输入是**实测** $u_{1,k},u_{2,k}$，而 MPC 下发的是**设定值** $u^{\text{set}}$。两者不一致会让模型系统性偏离。实测 TEC 恒流通道约 **8s 到位、误差 <1.5%**。

**方案 A（本装置采用）**

- $T_s$ 取 ≥ 执行器建立时间（实测 8s → 取 15s，同时 ≥ 温度更新周期）；
- 稳态误差 <2% 可忽略，**模型输入与优化变量统一用设定值 $u^{\text{set}}$**；
- 残余偏差与限压饱和由 ESO 的反馈修正自动吸收。

**方案 B（执行器慢于 $T_s$ 时必选，见 §10）**

$$
u_{k+1}=a_u u_k+(1-a_u)u^{\text{set}}_k
$$

把 $u$（实际值）增广进状态向量，MPC 优化 $u^{\text{set}}$，模型用 $u$。

**风扇惯性会串进 $u_1\to y$ 通道**

由于 TEC 冷量必须靠风传递（§2.3 路径①），风扇约 8s 的建立时间同时也串联在 TEC 通道上。$u_2$ 恒定时它表现为一个固定极点，被 $A_p$ 吸收，无害；但 $u_2$ 变化时该极点会移动。这是"增益随工作点漂移"的一个来源。

**更本质的一个来源（§2.3 第 3 条）**：$u_2$ 不只是"传递者"，它自身还是路径②这条制冷通道，换热量正比于 $(y_{true}-T_{wb})$。因此 $u_2$ 变化会**同时**移动对象极点（进 $A_p$）与输入增益（进 $B_p$ 第二列）。辨识时若不限制 $u_2$ 的变化范围，拟合出的 $A_p$ 只是全行程的某种平均，在任何一个具体工作点上都不准——这进一步强化了 §2.9 的工作区限制要求。

### 2.9 串级耦合的建模策略

§2.3 的乘积耦合使线性模型的可加性假设**只在局部成立**。三种处理策略，按落地难度递增：

**方案 1（推荐起步）：工作点线性化 + 工作区限制**

1. 用 §5.3 网格数据或 §5.5 数据选出标称工作点 $(u_1^0,u_2^0)$——取典型热负载下功耗最省的组合，且须落在 §2.2 命题 1 检验出的单调段内；
2. 在该点邻域内做**小幅联合激励**辨识，得到局部 $B_p$；
3. 用约束把运行区限制在「静态增益变化 < 20%」的范围内（用 §5.2 联合阶跃数据的局部斜率核查）；
4. 工作点漂移引起的残余增益变化，交给 ESO 的 $\hat d_k$ 吸收。

**方案 2（跨域需求强时）：双线性增广**

$$
\boldsymbol{x}_{p,k+1}=A_p\boldsymbol{x}_{p,k}+B_1u_{1,k}+B_2u_{2,k}+B_{12}\big(u_{1,k}u_{2,k}\big)+B_{2y}\big(u_{2,k}\,y_{true,k}\big)+\cdots
$$

$B_{12}$ 刻画路径①的串联耦合，$B_{2y}$ 刻画路径②的"换热系数 × 温差"饱和（§2.3 的 $g_{2y}$）。两个项都使优化非凸，需在 MPC 内做**逐次线性化**（每拍 2~3 次 SQP 迭代：固定上一轮的 $u_2$ 与 $y$ → 解 QP → 更新）。可行，但破坏"每拍一次 QP"的简洁性。

**方案 3（若方案 1 跨域失效，最实用）：分层解耦**

- **上层**：MPC 只优化一个标量「制冷需求」$q$，对象模型用 $q\to y$ 的线性模型 → **保持线性 QP 与凸性**；
- **下层**：用实测静态特性表，按**功耗最省**把 $q$ 分配成 $(u_1,u_2)$：

$$
(u_1,u_2)=\arg\min_{u_1,u_2}\;P_{tec}+P_{fan}\quad\text{s.t.}\quad Q_{net}(u_1,u_2)=q
$$

- 优点：**EMPC 的经济性由下层查表保证，本质不丢**；上层代码结构完全不变；
- 缺点：需离线建表 + 在线插值；$q$ 到 $(u_1,u_2)$ 是一对多映射，需定义清楚取哪一分支（通常取功耗最小的那一支）。

**推荐路径**：先用方案 1 上线，用 §5.7 的交叉验证量化跨域误差；若误差超标再上方案 3（比方案 2 更容易落地、风险更低）。

**风扇-TEC 联锁（硬性）**

由 §2.3，$u_2\approx0$ 时制冷效果≈0 而 TEC 白白耗电，故控制逻辑必须保证：

$$u_{1,k}>0 \;\Rightarrow\; u_{2,k}\ge u_{2,\min}$$

且**风扇故障 / 实测转速为 0 时强制 $u_{1,k}=0$**（见 §6.1）。这是逻辑约束、可行域非凸，不能放进 QP，必须写在**下发前的联锁判断**里。

**该联锁是单向的，不得反向套用**：$u_1>0\Rightarrow u_2\ge u_{2,\min}$ 成立，但**反过来不成立**——$u_2>0,\ u_1=0$（纯风扇制冷，§2.1 路径②）是**合法且常常最优**的运行方式。联锁逻辑与告警判据必须放过这种组合，绝不能把它当成"TEC 未投入"的异常去告警、去强制抬电流，否则会把最省电的解直接禁掉（§4.0）。

### 2.10 全局增广状态空间（ESO 与 MPC 的统一预测模型）

$$
\boldsymbol{x}_k = \begin{bmatrix} \boldsymbol{x}_{p,k} \\ d_k \\ x_{s,k} \end{bmatrix}
$$

$$
\boldsymbol{x}_{k+1}
=
\underbrace{
\begin{bmatrix}
A_p & B_d & \mathbf 0 \\
\mathbf 0 & 1 & 0 \\
b_s C_p & 0 & a_s
\end{bmatrix}
}_{A}
\boldsymbol{x}_k
+
\underbrace{
\begin{bmatrix}
B_p \\ \mathbf 0 \\ \mathbf 0
\end{bmatrix}
}_{B}
\begin{bmatrix} u_{1,k} \\ u_{2,k} \end{bmatrix}
+
\underbrace{
\begin{bmatrix}
B_m \\ \mathbf 0 \\ \mathbf 0
\end{bmatrix}
}_{B_m^{a}}
m_k
$$

**观测输出方程（单测量）**

$$
y_{w,k}
=
\underbrace{\begin{bmatrix} \mathbf 0 & 0 & 1 \end{bmatrix}}_{C}
\boldsymbol{x}_k
$$

矩阵结构的含义：

- 第二行 $\begin{bmatrix}\mathbf 0 & 1 & 0\end{bmatrix}$：积分扰动 $d$ 自身递推；
- 第三行 $b_s C_p$：探头状态由**真实水温** $y_{true}=C_p x_p$ 驱动，而不是由读数驱动；
- $C$ 只取 $x_s$：唯一能观测到的是探头读数。

## 3 ESO 扩展状态观测器

ESO 的任务是从**一路带滞后的水温读数**中，同时估计出：真实水温 $y_{true}$、不可测热负载 $d$、以及对象的内部状态。

### 3.1 算法：先验/后验分离

**第一步 — 先验预测（时间更新）**

$$
\hat{\boldsymbol{x}}_{k\mid k-1}=A\hat{\boldsymbol{x}}_{k-1\mid k-1}+B\boldsymbol{u}_{k-1}+B_m^{a}m_{k-1}
$$

**第二步 — 后验修正（测量更新）**

$$
\hat{\boldsymbol{x}}_{k\mid k}=\hat{\boldsymbol{x}}_{k\mid k-1}+L\big(y_{w,k}-C\hat{\boldsymbol{x}}_{k\mid k-1}\big),
\qquad L\in\mathbb{R}^{n\times1}
$$

**输出（均取后验，供 MPC 使用）**

$$
\hat y_{true,k}=C_p\hat{\boldsymbol{x}}_{p,k\mid k},\qquad
\widehat{\Delta T}_k=T_{hot,k}-\hat y_{true,k},\qquad
\hat d_k
$$

其中 $T_{hot,k}$ 取 `shuitong_temp` 的可测扰动值。

**为什么必须严格区分先验与后验**

MPC 需要的是"当前时刻状态的最佳估计"，即已经用上最新测量 $y_{w,k}$ 的**后验** $\hat{\boldsymbol{x}}_{k\mid k}$。

若写成一步预测（predictor）形式 $\hat{\boldsymbol{x}}_{k+1}=A\hat{\boldsymbol{x}}_k+B\boldsymbol{u}_k+L(y_k-C\hat{\boldsymbol{x}}_k)$，则式中的 $\hat{\boldsymbol{x}}_k$ 实际上是**先验**——它没有用上 $y_k$，比后验滞后一拍。此时若再把 $C_p\hat{\boldsymbol{x}}_{p,k}$ 当作"当前真实温度"交给 MPC，等于让控制器基于一个尚未更新的状态做决策，在快速工况下会产生一整拍的系统性滞后。

正确做法就是上面的两步：先矫正到后验 $\hat{\boldsymbol{x}}_{k\mid k}$，再以此为起点向后预测。

### 3.2 单测量架构的能力边界

水温是**慢**通道。热负载突变后，必须等水温开始偏离模型预测值、残差 $(y_w-C\hat x)$ 出现，$\hat d_k$ 才开始被修正。

因此**「在温度升起来之前提前识别负载突变」在本架构下做不到**。能做的是：让 $\hat d_k$ 在残差出现后的少数几个采样步内**快速收敛**（靠 $Q_d$/$\omega_o$），把超温幅度压到最小。这是 §0.2 决定不引入快通道测量的直接代价，也是 §2.5 中 $\mathrm{cond}(\mathcal{O})$ 检查必须强制执行的原因。

### 3.3 观测增益设计

- **Kalman（推荐）**：给定过程噪声 $Q$（其中 $Q_d$ 控制 $d$ 的游走速度，$Q_d$ 越大跟踪越快）与测量噪声 $R=\sigma_w^2$（水温探头的量化 + 抖动实测方差），解稳态 Riccati 方程得 $L$；
- **带宽法（ADRC 风格，单参数）**：把全部观测器极点配置到 $\lambda=e^{-\omega_o T_s}$，只调 $\omega_o$。

调参边界：$\omega_o$ 的上限受**温度更新周期（15s）与量化噪声（0.1℃）**约束。起始值取 $\omega_o\approx(2\sim5)/(\text{对象主导时间常数})$，再按残差与噪声放大折中。

**单测量下提高 $\omega_o$ 的噪声放大代价更大**，调参时应以**残差的噪声放大倍数**（而非收敛速度）作为硬约束。

### 3.4 传感器偏置增广（可选）

若探头存在零点误差，$d$ 会把它当成热负载吸收，造成稳态偏差。可增广一个偏置状态：

$$b_{k+1}=b_k,\qquad y_{w,k}=x_{s,k}+b_k$$

**注意**：单测量下 $b$ 与 $d$ 在稳态**不可区分**——二者都产生常值输出偏移。只有当系统存在足够的输入激励（$u$ 持续变化）时二者才可分离。若运行工况激励不足，则不增广，改为**离线标定探头零点**。

## 4 EMPC 经济模型预测控制

### 4.0 稳态目标计算（EMPC 稳定性的前提）

每拍**先**解一次稳态优化，得最优稳态工作点 $(\bar u_1,\bar u_2,\bar x)$：

$$
\min_{\bar u_1,\bar u_2}\; R_{tec}\bar u_1^2+S_{tec}\widehat{\Delta T}_k\,\bar u_1+f_{fan}(\bar u_2)
\quad\text{s.t.}\quad
\bar y_{true}=T_{ref},\ \ \bar u\in[\underline u,\bar u]
$$

该工作点作为终端约束的目标。

> **注意：稳态最优解很可能是 $\bar u_1=0,\ 0<\bar u_2\le u_{2,\max}$**。因为风扇自身就是一条制冷路径（§2.1 路径②），只要 $T_{ref}>T_{wb}$ 纯吹风即可达标，而风扇功耗通常比 TEC 低一个数量级。这是**期望结果**，不是异常，绝不能被 §2.9 的风扇-TEC 联锁、或被任何"TEC 通道没用上"的判据误伤。只有当 $T_{ref}<T_{wb}$（或要求的降温速率超出风扇能力）时，$\bar u_1$ 才会大于 0。

**为什么经济 MPC 必须有终端约束**

常规跟踪 MPC 的目标函数是 $\lVert y-r\rVert^2+\lVert u\rVert^2$ 这类关于设定值的**正定二次型**，其稳定性有标准证明。而经济 MPC 的目标函数是**运行成本**（此处为功耗），它关于 $(y,u)$ 并不正定，也不以设定点为最小值。后果是：

- 有限时域滚动优化会在预测末端把输入推向"最经济"的值——在本装置中就是 $u_1=u_2=0$（不制冷最省电）；
- 预测时域一滚动，末端位置就变，最优解随之抖动，甚至引发闭环振荡或失稳。

解决办法是给优化加上**终端约束**（或等价的终端代价，即"到最优稳态工作点的距离"这一凸函数）：强制预测末端落在 §4.0 算出的最优稳态工作点上。这样闭环才会渐近收敛到**最优稳态**，而不是在"省电"与"控温"之间反复摇摆。

### 4.1 目标函数

$$
\begin{aligned}
J =&\ \sum_{i=0}^{N_p-1} \Big(R_{tec} u_{1,k+i}^2 + S_{tec}\widehat{\Delta T}_k\, u_{1,k+i} + f_{fan}(u_{2,k+i})\Big) \\
&+ \lambda_1 \sum_{i=0}^{N_c-1}\Delta u_{1,k+i}^2
 + \lambda_2 \sum_{i=0}^{N_c-1}\Delta u_{2,k+i}^2
 + \rho \sum_{i=1}^{N_p} \varepsilon_{k+i}^2
\end{aligned}
$$

- **第一项**：预测时域内的 TEC + 风扇累计功耗。**求和区间必须与约束区间一致（$0..N_p-1$）**。若只累加到 $N_c-1$，则 $i\ge N_c$ 段的控制动作在目标里"免费"，优化器会在这段随意取值，造成目标与约束的时域错配；
- **第二、三项**：控制增量平滑惩罚，抑制电流/电压剧烈跳变，保护硬件并避免激发未建模动态；
- **第四项**：松弛惩罚。**长期运行模式下 $\rho$ 应取足够大（按对偶变量上界估计），使 $\varepsilon$ 实际恒为 0**——它只为**数值可行性**保留（避免约束矛盾时 QP 无解），不是用来"允许超温"的。$\varepsilon>0$ 持续出现即代表物理不可行，必须触发告警（§6.1）。
  **对比实验模式（§11）**：超温段直接**全功率接管**、不进 QP（§11.4.2），QP 只在带内工作。因此 $\varepsilon$ 的角色不变（仍是纯数值可行性），只是 $\varepsilon>0$ 在"初始越限"与"注水跳变"期间是预期的——该段由接管层兜底，告警判据见 §6.1。**不需要**给超温定价，也不需要改成 $\ell_1$。

其中

$$
\Delta u_{k+i}=u_{k+i}-u_{k+i-1},\qquad i=0,1,\dots,N_c-1
$$

$i=0$ 时的 $u_{k-1}$ 为**上一拍实际下发值**（已知常数）。注意 $\Delta u$ 的求和范围必须与约束中 $\Delta u$ 的下标范围完全一致。

### 4.2 约束条件

$$
\begin{align*}
&T_{\min} \le \hat y_{true,k+i\mid k} \le T_{\max} + \varepsilon_{k+i},\quad \varepsilon_{k+i}\ge0,\quad i=1,\dots,N_p \\[4pt]
&\hat y_{true,k+N_p\mid k} \le T_{\max}-\delta \qquad\text{（终端余量，}\delta\ge3\sigma_{model}\text{）}\\[4pt]
&0 \le u_{1,k+i} \le u_{1,\max},\quad i=0,\dots,N_c-1 \\[4pt]
&u_{2,\min} \le u_{2,k+i} \le u_{2,\max},\quad i=0,\dots,N_c-1 \\[4pt]
&-\Delta u_{1,\text{lim}} \le \Delta u_{1,k+i} \le \Delta u_{1,\text{lim}},\quad i=0,\dots,N_c-1 \\[4pt]
&-\Delta u_{2,\text{lim}} \le \Delta u_{2,k+i} \le \Delta u_{2,\text{lim}},\quad i=0,\dots,N_c-1
\end{align*}
$$

**关键说明**

1. **约束必须使用预测的真实水温 $\hat y_{true}$，而不是滞后读数 $y_w$**。用 $y_w$ 等于把探头的滞后当作安全裕度，实际温度早已越限而控制器仍认为安全。这是抗突变、保安全的核心；
2. **$i\ge N_c$ 时控制量保持 $u_{k+N_c-1}$ 不变**（实现时必须明确，否则会产生歧义）；
3. **温度下限 $T_{\min}$ 不可省**：TEC 5A 可把水温压得很低，无下限约束会过冷；
4. **$\varepsilon$ 的角色**仅为数值可行性。超温约束在物理上应视为**硬约束**；一旦 $\rho$ 不够大，就等于给"超温"定了个价，实际温度会真的冲过 $T_{\max}$。（对比实验模式下超温段由 §11.4.2 的全功率接管负责、不进 QP，因此这条**保持不变**：仍然不给超温定价。是否要给超温定价，取决于考核口径是否真的在给超温计分——本题不计分，所以不定价。）
5. **不设结露约束**：本场景为开放水杯，冷端结露不构成实际风险（无电子器件暴露在冷端）。若日后改为封闭机柜/电子器件工况，需重新引入送风露点约束，届时还需要湿度传感器与冷端测点；
6. **风扇死区与 QP 可行域**：低于启动电压风扇不转，$u_2$ 在该区间内是"无效控制量"。若业务上允许完全关断，可行域变为 $\{0\}\cup[u_{2,\min},u_{2,\max}]$ 的**非凸集合**，严格处理需要整数变量（MIQP）。工程简化用两段式逻辑：水温**已接近/低于 $T_{\min}$ 且预测仍会继续下降**时直接关断并令 $u_2$ 约束为 0（此时要关掉的正是路径②自身的制冷能力），否则强制 $u_2\ge u_{2,\min}$，从而保持 QP 结构。**切勿**把"水温已低于 $T_{\max}$（即已在带内）"当作关风扇的条件——路径②是低成本制冷手段，在带内提前关风扇只会让水温回升、随后被迫投入更贵的 TEC（§2.2 命题 4）；
7. **风扇-TEC 联锁（叠加在第 6 条之上）**：由 §2.3，制冷量只能靠风传递，故 $u_1>0$ 时必须满足 $u_2\ge u_{2,\min}$。若 QP 解出 $u_1>0$ 而 $u_2<u_{2,\min}$，优先直接令 $u_1=0$（更安全），其次才考虑把 $u_2$ 抬到 $u_{2,\min}$ 后重解。该判断写在下发前，**不进 QP**。反之，若解出 $u_1=0$ 且 $u_2\ge u_{2,\min}$，属纯风扇制冷的正常最优解，**不做任何干预**（§4.0）；
8. **功耗模型不含 $u_1u_2$ 交叉项**（§2.3）：两个输入由**独立控制电源**供电，总功耗严格可加，$P=P_{tec}(u_1)+P_{fan}(u_2)$；串级耦合只存在于制冷通道，不出现在功耗侧。因此目标函数天然保持可加与凸性，串级耦合**不影响** QP 的凸性。§5.3 第 4 项检验负责验证该假设。
9. **两种运行模式，终端条件不同，不可混用**（§11.5）：
   - **长期运行模式**（默认）：固定 $N_p$、$N_c$，终端约束指向 §4.0 的最优稳态工作点，保证渐近稳定性；
   - **对比实验模式**（45 min 定时长实验）：**收缩时域** $N_k=(T_{end}-t_k)/T_s$，终端约束换成"终端温度 $\le T_{end}^*-\delta$"，不要求渐近稳定（跑到终点就停）；预测时域内跨越注水事件时按 §11.2 注入状态跳变。
   
   两者用开关切换。把长期运行模式的终端条件直接拿去做定时长实验，会因"终端需落在最优稳态"而多耗电；反过来把收缩时域用于长期运行则会失去稳定性保证。

### 4.3 QP 形式与求解

整理成标准凸 QP：$\min_z \tfrac12 z^\top H z + c^\top z,\ \text{s.t. } Gz\le h$，其中 $z=[\boldsymbol{u}_1;\boldsymbol{u}_2;\boldsymbol{\varepsilon}]$。

- **$H$ 必须半正定**：$\lambda_1,\lambda_2,\rho>0$，$R_{tec}>0$，$f_{fan}$ 凸（§2.7）；
- 规模：$N_p=40,N_c=10$ 时约 60 个变量、200+ 约束，OSQP / qpOASES / CVXPY 均可在毫秒级求解，满足 15s 周期；
- **热启动**：用上一拍的解作为初值，可显著减少迭代次数。

### 5.1 数据采集通用规范

**采样周期**：$T_s=15$s。

**选取原理**：$T_s$ 必须落在由硬件决定的**下界**与由控制性能决定的**上界**之间；本装置取下界，理由见下。

**下界——由硬件钳死，不能再快**

| # | 约束 | 机理 |
| --- | --- | --- |
| 1 | $T_s\ge T_{update}=15$s（LoRa 温度更新周期） | 快于它则同一读数被重复采样，等效给测量通道加零阶保持；样本数增加而信息量不增加，ESO 噪声特性失真、辨识有偏 |
| 2 | $T_s\ge t_{settle}=8$s（执行器建立时间） | 否则下发设定值与实测值不一致，模型输入 $u$ 与实际作用量不符（§2.8） |

$\Rightarrow\ T_s\ge\max(15,\,8)=15$s。

**上界——由控制性能决定，不能再慢**

| # | 约束 | 机理 |
| --- | --- | --- |
| 3 | **闭环带宽准则** $T_s\le\tau/10$ | 一个主导时间常数内至少 10~20 个采样点。定量依据见下 |
| 4 | **扰动识别速度**（单测量下最紧的一条） | §0.2 决定只用慢水温通道，$\hat d_k$ 只能在残差出现后逐拍收敛。$T_s$ 越大，一个采样周期内累积的温升越大，超温幅度近似正比于 $T_s$ |
| 5 | **MPC 时域分辨率** $N_pT_s\gtrsim4\tau$ | 预测时域须覆盖对象主导动态，否则终端约束/终端代价管不住尾部发散；$T_s$ 过大会迫使 $N_p$ 剧增或时域不足 |

**准则 3 的定量依据（"10~20 点"是怎么来的）**

> **先澄清一处措辞**：对 LTI 对象 + ZOH 输入，$A_d=e^{A_cT_s}$ 是**精确**离散化，本身不是近似。真正的失效机理是——$T_s$ 相对 $\tau$ 过大时，对象动态被压缩进单个采样步，**信息丢失**。

一阶对象的离散极点为 $a=e^{-T_s/\tau}$，单拍内完成的响应比例为 $1-a$：

| $T_s/\tau$ | 每 $\tau$ 采样点数 | 离散极点 $a$ | 单拍完成比例 $1-a$ |
| --- | --- | --- | --- |
| 0.05 | 20 | 0.951 | 4.9% |
| 0.10 | 10 | 0.905 | 9.5% |
| 0.20 | 5 | 0.819 | 18% |
| 0.50 | 2 | 0.607 | 39% |
| 1 | 1 | 0.368 | 63% |
| 3 | 0.33 | 0.050 | 95% |
| 5 | 0.2 | 0.0067 | 99.3% |

当 $T_s\gtrsim3\tau$ 时单拍就走完 95% 以上，后果分两层：

1. **辨识层**：$a\approx0$，离散模型退化成纯增益 $y_{k+1}\approx bu_k$，$\tau$ **不可辨识**（所有快于此尺度的对象在离散数据里看起来都一样；$a$ 的微小估计误差对应 $\tau$ 的巨大误差）；
2. **控制层**：反馈量到的已是"过程结束后的结果"，控制器实质上在开环工作。

**"10~20 点"有两个独立来源，量级一致**：

**(a) 单拍响应幅度**：要求一拍内的变化是小量（$\lesssim10\%$），才谈得上"逐拍修正" → $T_s/\tau\le0.1$ → **≥10 点/τ**。

**(b) ZOH 相位滞后**：ZOH 等效在环路中引入 $T_s/2$ 的纯延迟，在穿越频率 $\omega_c$ 处相位损失为

$$
\Delta\phi=\frac{\omega_c T_s}{2}\quad\text{(rad)}
$$

取闭环带宽为对象带宽的 $k$ 倍（$\omega_c=k/\tau$，即"闭环比对象快 $k$ 倍"），要求 $\Delta\phi\le5^\circ\sim10^\circ$，解得每 $\tau$ 的最少点数 $N=\tau/T_s\ge k/(2\Delta\phi)$：

| 加速倍数 $k$ | $\Delta\phi\le5^\circ$ | $\Delta\phi\le10^\circ$ |
| --- | --- | --- |
| 1（闭环与对象同速） | 5.7 点/τ | 2.9 点/τ |
| 2 | 11.5 点/τ | 5.7 点/τ |
| 3 | 17 点/τ | 8.6 点/τ |

工程上典型组合是"闭环比对象快 2~3 倍、相位损失控制在 5°~10°" → **11~17 点/τ**，这就是常说的 **10~20 点**。

**对本装置的含义**：$\tau$ 估计数百秒，$T_s=15$s → $15/300=0.05$ → **20 点/τ**，落在区间上限，非常充裕。因此**本装置的 $T_s$ 实际上不由这条决定**——真正的紧约束是下界的 15s 温度更新周期，以及上界的准则 4（扰动识别速度）。

**为什么取下界而不是区间中点**

在 [下界, 上界] 内，控制性能（扰动识别速度、约束满足精度、时域分辨率）随 $T_s$ 减小**单调变好**；而代价——每 15s 解一次 QP、485 下发次数——在本装置上完全不敏感。既然慢下来没有收益、快起来有收益，取下界 15s 即为最优。这与"采样越快越好"的直觉相反：真正的下限是被**信息速率**（温度 15s 更新）而非算力钳住的。

**⚠ 待回验：第 3 条中的 $\tau$ 目前是估计值，未实测**

§5.5 辨识出 $A_p$ 后必须回验上界：

- 若 $\tau\ge150$s → $T_s=15$s 满足 $T_s\le\tau/10$，取值成立；
- 若 $\tau<150$s → **上下界无交集**。这意味着 15s 的温度更新速率根本不足以控制该对象——不是调参能解决的，必须换更快的温度传感器。这是辨识后第一个要检查的结论。

**$\tau$ 怎么拿到**（两档精度，不必等 §5.5 完整辨识）：

1. **快估（现在就能做）**：`model/tec_prbs_analyze.py` 已在第 146 行按 `tau = -TS/math.log(a)` 换算，并在 `report()` 中打印 `tau=...s`。跑一次脚本，读"慢通道 剔除初始段"那行即可。注意这是 FOPDT **一阶等效** τ——若对象实为高阶，它会把多个极点混成一个等效值（通常偏大），但对上面的 $\tau\ge150$s 判断足够；
2. **精确（§5.5 之后）**：从辨识出的 $A_p$ 特征值反推。取**最慢**极点（$a$ 最接近 1、离单位圆最近的那个）：$\tau=-T_s/\ln a_{\max}$。多极点系统中"主导"即指它，因为闭环能达到多快由最慢的极点封顶（木桶效应）。

> **$\tau$ 过大也不是好事**：若对象接近积分器（$a\to1$，$\tau\to\infty$），准则 3 会**自动满足**，但准则 5（$N_pT_s\gtrsim4\tau$）**永远满足不了**——settling time 无穷大，预测时域管不住尾部。这正是 §4 必须保留**终端约束/终端余量**与 §4.0 **稳态目标计算**的原因：用终端条件兜住尾部，而不是靠加长时域。因此回验时不能只看"$\tau\ge150$s 通过"，还要看 $\tau$ 是否已大到让终端约束成为必需。

**⚠ 名义 $T_s$ ≠ 有效测量更新率（易踩坑）**

读数有 0~15s 随机抖动且存在丢包，故 $T_s=15$s 时**并非每拍都有新读数**，有效更新间隔在 15~30s 间随机。两点必须落实：

- 重复读数（`temp_new=0`）**不触发测量更新**，该拍只做时间更新（§6 步骤 2）——否则同一个残差被重复修正，ESO 会过冲；
- ESO 的 $R$ 与 $\omega_o$ 应按**有效更新率**整定，而不是名义 15s。按 15s 整定等于让观测器"以为"每拍都有新信息，增益过激、放大噪声。

**时间戳对齐（必做）**

温度通道是 LoRa 终端，读数**随机滞后 0~15s**。若把读数直接记在名义时刻 $t$ 上，等于给输出通道加随机纯延迟，辨识结果有偏。CSV 每行必须附带 `temp_age`（本拍各温度通道里最大的 age）：

- 用 $t-temp\_age$ 还原读数的真实时刻，重建时间轴后用等间隔重采样；
- `temp_new`（0/1）标记本拍是否有新上行，只取 `temp_new=1` 的行可得无重复序列；
- **age 超阈值（45s）的读数按缺测写空后插值**——现场应答率不足时 age 可达数分钟，把陈旧值当新值写入等于伪造动态轨迹。

**缺测与插值**：功率/电流/电压（1~2s 更新）与温度（15s）不同步，回归时温度取"最近一次有效值"并限制 age。

**实验期间必须固定的硬件条件**：风道与进出风口开度、散热片与风扇相对位置、目标水杯水量（液位）、冷却水流量/水泵档位、门窗关闭（避免空调启停与日照）。实验开始前系统应已稳态（建议预热/预冷 10~30 min）。

### 5.2 执行器通道特性测试（设定值 → 实际值）

**目的**：确认 MV 定义正确、建立时间、稳态误差、饱和与死区。不做这一步，后面所有数据都可能作废。

**两个对称的坑（必须先确认）**

| 设备 | 必须的工作模式 | MV | 反例后果 |
| --- | --- | --- | --- |
| `zhileng-power`（制冷片） | **恒流** `work_mode=1` | `current_set` | 若停在恒压，`current_set` 退化成限流上限，电流不跟随 → 整段数据作废 |
| `fengshan-power`（风扇） | **恒压** `work_mode=0` | `voltage_set` | 若停在恒流，`voltage_set` 无意义，风扇电压不跟随 → 同样作废 |

每次启动都必须回读校验（`output_on=1`、模式字、设定值）。**只看写返回码会漏判**——这台电源出现过"写入返回成功但回读不变"（485 地址不匹配）。

**测试内容**

1. **TEC 通道**：$I_{set}$ 阶跃 0 → 1 → 2 → 3 → 4 → 5 → 3 → 1 → 0 A（含回程，检验滞环），每点驻留 30s，1~2s 高频记录实际 $I,V,P$。
   - 实测参考：3.0A→2.99A/6.75V、2.0A→2.02A/4.99V、4.0A→3.97A/9.21V，误差 <1.5%，8s 到位；
   - 记录**建立时间 $t_{settle}$**（进入 ±2% 带并保持）；
   - **限压检测**：实际电压 ≥ 0.98×24V 判定顶到限压，该点剔除（此时电流会掉下来跟不上设定）。
2. **风扇通道**：$V_{set}$ 阶跃 0 → 4 → 8 → 12 → 16 → 20 → 24 V（含回程），每点驻留 30s，记录实际 $V,I,P,pwm\_duty$。
   - **找启动死区 $u_{2,\min}$**：低于某电压风扇不转（功率很小且无风），该点以下为无效控制量 → 直接决定 §4.2 的 $u_{2,\min}$；
   - 记录建立时间。
3. **交叉验证**：给 TEC 加电流时观察风扇功率是否变化，反之亦然。两路为独立电源，**预期无耦合**；若测到（共母线/共电源导致），属电气耦合，与 §2.3 的制冷耦合是两回事，按 §5.3 第 4 项处置——排查供电拓扑，不要把交叉项写进模型。
4. **联合阶跃（必做）**：TEC 冷量必须经风扇传递（§2.3 路径①），**单独做 $u_1$ 阶跃而 $u_2=0$ 时水温几乎不动**——这不能判定"$u_1$ 通道无效"，只能说明没有风。必须补做联合阶跃：在 $V_{fan}\in\{6,12,18,24\}$ V 各档位下分别做 $I$ 的 0→2→4→2→0 A 阶跃（或反之，在若干 $I$ 档位下扫 $V_{fan}$），记录各档下的稳态水温降幅。
   - 用途一：得到静态增益 $\partial y/\partial u_1$ 随 $u_2$ 的变化曲线，用于核定 §2.9 方案 1 的"增益变化 <20%"工作区；同时检验 §2.2 命题 1（降温幅度是否随电流增大而回落），据此定出单调段上界；
   - 用途二：验证 $u_2$ 过小档位下制冷确实失效，为 §4.2 的 $u_{2,\min}$ 与风扇-TEC 联锁提供实测依据；
   - **驻留时间按热响应给**（每点 ≥5 min，或至少覆盖 63% 过渡过程）。这比纯电气测试慢得多，需单独安排，不要混进 15 分钟的电气测试里。
5. **纯风扇阶跃（必做）**：$u_1=0$ 固定，做 $V_{fan}$ 的 0→6→12→18→24→12→0 V 阶跃，每点驻留 ≥5 min，记录稳态水温与 `env-temp`。
   - **用途一**：实测路径②的制冷能力，**确认"只开风扇确实能降温"**——这是推翻 $Q_{net}(0,u_2)=0$ 这个错误假设的直接证据；
   - **用途二**：量出该通道的**温度下限**——稳态水温与 `env-temp`（干球）之差即蒸发冷却的贡献，实际极限是湿球温度 $T_{wb}$。它决定了"哪些目标温度可以只靠风扇达成"（§2.2 命题 4）；
   - **用途三**：给出降温幅度对 $u_2$ 的静态曲线，与 §5.3 的风扇功耗曲线合并即可算出**风扇的能效比**，并与 TEC 对比，定出投入优先级；
   - **没有湿度测点时的处理**：用 `env-temp` 作 $T_{wb}$ 的保守代理（湿球 ≤ 干球）。这会**低估**风扇能力，偏差方向是安全的（实际能降得比预测更低）。若该通道重要，建议补一路湿度/湿球测点。

**判定与处置**

- $t_{settle}\le T_s/2$ 且稳态误差 <2% → 采用 §2.8 方案 A（设定值即模型输入）；
- 否则 → 采用方案 B（增广执行器一阶滞后），或把 $T_s$ 放大到 $\ge t_{settle}$；
- 滞环 >5% → 需在模型中增加滞环补偿，或限制单向调节。

### 5.3 功耗特性扫描（实际值 → 功率）

**为什么必须做**：功耗模型就是 EMPC 的**目标函数本身**。热模型错了只是"控不准"，功耗模型错了是**系统性地选错最优点**——控制器以为在省电，实际跑到低效区，而且曲线看着很稳，极难发现。此外它是纯电气量、无热惯性，**15 分钟即可完成**，与需要 90 分钟的热辨识相比性价比极高。

**关键：TEC 功耗不是电流的单值函数**

**不能只扫电流**：$P_{tec}$ 到底依赖哪些量、以什么形式依赖，本身就是待判定的问题（候选见 §2.7）。若它确实还依赖 $\Delta T$，那么只扫电流不记温度拟合出的系数换个工况就偏。

**实验设计：双因素网格**

- $I\in\{0,1,2,3,4,5\}$ A × $V_{fan}\in\{0,6,12,18,24\}$ V，共 25 个工况点；
- 每点驻留 30s（电气量早已稳定），**同步记录温度**（水温 `servers-temp` 为必记，热端冷却水 `shuitong-temp` 用于 $\Delta T$）；总时长约 15 分钟；
- **网格实验不能替代 §5.5 的热辨识**：每点只驻留 30s，远小于热时间常数（数百秒），水体根本没响应就换点了。它只能提供**静态/电气**信息（功耗模型、死区）。热模型的动态必须靠 §5.5 的 PRBS 实验（每电平 ≥75s）；制冷耦合的静态特性则靠 §5.2 第 4 条的联合阶跃（每点 ≥5 min）；
- **实验安全**：网格中含 $V_{fan}=0$ 且 $I$ 较大的点，此时冷量散不出去、$\Delta T$ 会被拉到很大。该点**只做短时采样（≤30s）并尽快离开**，不要长时间驻留——此时冷量散不出去、$\Delta T$ 被拉到极大，属于既不制冷又费电的无效工作点。

**为什么短驻留即可**：功耗是准静态电气量，响应远快于热响应。$\Delta T$ 在扫描过程中自然变化，反而为回归提供了所需的 $\Delta T$ 变化范围。

**回归模型**

TEC（以 §2.7 候选 T1 为例的三列线性回归；换成其它候选时相应改设计矩阵）：

$$
\Phi_{tec}=\begin{bmatrix}
I_1^2 & I_1\Delta T_1 & 1\\
I_2^2 & I_2\Delta T_2 & 1\\
\vdots & \vdots & \vdots
\end{bmatrix},\qquad
\begin{bmatrix}R_{tec}\\ S_{tec}\\ P_0\end{bmatrix}=(\Phi^\top\Phi)^{-1}\Phi^\top\boldsymbol{P}_{tec}
$$

其中 $\Delta T = $ `shuitong_temp` − `servers_temp`（热端冷却水温度 − 被控水温，见 §2.7）。

风扇（**模型竞争，禁止预设**）：对 $au_2^2$、$au_2^3$、$au_2+b$、带死区分段线性分别拟合，按**测试集 RMSE + AIC** 选优。

**必做的四项检验**

1. **$R_{tec}>0$ 检验**：拟合为负说明共线性/过拟合 → 改用 NNLS 重拟合（§2.7 凸性保障）；
2. **$\Delta T$ 项显著性**：看 $S_{tec}$ 是否显著非零；更直接的验证是"同一 $I$ 下改变 $V_{fan}$，$P_{tec}$ 是否变化"——网格实验直接给出答案。**注意此处测到的是间接效应**（$V_{fan}\to$ 水温 $\to\Delta T\to P_{tec}$，见 §2.3），不是交叉项。显著则说明 $\Delta T$ 通道确实起作用，必须走冻结 $\Delta T$ 方案；
3. **自洽性**：$P_{tec}\stackrel{?}{=}I\cdot V$（用 `power` 与 `current`×`voltage` 互校），偏差 >5% 说明点位 scale/寄存器配置有问题，先修采集；
4. **交叉项显著性（验证电源独立假设）**：在选定模型基础上**额外加一列 $u_1u_2$** 做对照拟合，检验其系数是否显著为 0。由 §2.3，**预期不显著**。若显著，说明存在共电源/共母线等**电气**耦合——这属于硬件事实与建模假设不符，应当去排查供电拓扑，**而不是把交叉项写进模型**（写进去会把 Hessian 变成不定矩阵，直接破坏凸 QP）。

### 5.4 探头时间常数标定 $\tau_s$

只需标定**水温探头**一路。

**方法**：独立的探头阶跃实验——把探头从一个恒温水槽迅速移入另一个（温差 ≥10℃），记录响应曲线，最小二乘拟合指数曲线得 $\tau_s$。

装置上没有比 LoRa 探头更快的参考传感器，因此无法用"同步记录高精度真值"的办法。可选的替代方案是把 $\tau_s$ 作为未知参数与对象参数**联合辨识**（外层网格搜索 $\tau_s$、内层最小二乘）。

**可分离性警告**：若 $\tau_s$ 与对象主导时间常数 $\tau_p$ 量级相近，从 $u\to y_w$ 串联得到的两个极点**不可分离**（无法判断哪个极点属于探头、哪个属于对象）。此时必须靠独立的阶跃实验把 $\tau_s$ 定死，不能指望联合辨识。

按 §2.6 的 ZOH 口径计算 $a_s,b_s$。

### 5.5 热对象单输出辨识

**输入**：$u_1$（PRBS 5 电平）、$u_2$（另一条 PRBS，与 $u_1$ 长度互质或相位错开）、可测扰动 $m$（室温 `env-temp`、冷却水 `shuitong-temp`）
**输出**：$y_w$（水温）——**单输出**

**方法**

- 推荐 **N4SID / MOESP 子空间辨识**（无需参数化初值）；
- 或 PEM / 输出误差法直接对 §2.4 的结构估参数；
- **先辨识 $u\to y_w$ 的整体模型**（含探头滞后），再按 §5.4 已知的探头极点**解耦**出 $A_p,C_p$；
- **严禁先逆滤波**（原理见 §2.6）。

**阶次选择**：奇异值拐点 + AIC/BIC + 测试集自由仿真误差三者交叉确定，不要只看训练误差。

**激励设计**：5 电平 PRBS（GF(5) m-sequence，天然满足持续激励条件）、每电平保持 ≥5 个采样周期（$5\times15$s=75s，保证温度有响应时间）、总采样点 ≥800。运行前用 `--plan-only` 自检，检查信息矩阵条件数（脚本已有 `PE_COND_LIMIT`）。

**双输入联合激励是硬性要求**（原理见 §2.3）

制冷量必须经风扇传递，$\partial y/\partial u_1$ 本身是 $u_2$ 的函数。**任何"固定一个输入、只激励另一个"的数据，都只能给出该固定工作点下的局部通道增益，不能支撑跨工作区的模型**。具体要求：

- $u_1$、$u_2$ 用两条**长度互质或相位错开**的 5 电平 PRBS，全程同时变化，保证二者在样本上近似独立；
- **联合工作区覆盖**：$(u_1,u_2)$ 的二维散点应覆盖预期运行矩形，且**避免落在 $u_2<u_{2,\min}$ 的无效区**（那里两条路径同时断、制冷恒为 0，只会污染辨识）；
- **水温覆盖范围（路径②带来的新要求）**：路径②的增益随 $(y_{true}-T_{wb})$ 衰减（§2.3）。若辨识数据只在中高温段取得，则用该模型在低温段会**高估**风扇制冷能力 → 预测温度偏低 → 约束判断偏乐观 → 实际超温。因此数据必须覆盖预期运行的水温区间，且 $u_1=0$ 的纯风扇段要有足够样本；
- 若最终采用 §2.9 方案 1（工作点线性化），则 PRBS 幅度应**收窄到标称点邻域**（各 ±20% 左右），而不是全域大幅激励——全域激励拟合出的是"平均模型"，在标称工作点处反而不准。

**必须开环**：辨识期间不得有任何温度反馈调节，否则输入与扰动相关，估计有偏。

### 5.6 组装与 ESO 增益

1. 把 $A_p,B_p,C_p,B_m,a_s,b_s$ 代入 §2.10 组装 $A,B,C$；
2. 按 §2.5 设定 $B_d$；
3. 按 §3 设计 $L$（Kalman 或带宽法）；
4. **数值检查 $\mathrm{cond}(\mathcal{O})$**，超 $10^6$ 回到 §2.5 重新设计；
5. 按 §4 初始化 EMPC 参数（$N_p,N_c,\lambda,\rho,\delta$、上下限、增量限幅）。

### 5.7 模型验证与准入

| 检验项 | 方法 | 准入门槛 |
| --- | --- | --- |
| 训练/测试切分 | 前 80% 训练、后 20% 测试 | — |
| **自由仿真误差** | 多步递归预测（非一步预测） | NRMSE < 10% |
| 一步预测误差 | 对照用 | — |
| 残差白噪声 | ACF 检验，除 0 阶外落入 95% 置信界 | 通过 |
| 阶次合理性 | 奇异值拐点 + AIC | 一致 |
| 不同工况交叉验证 | 换一批数据验证 | 不显著退化 |
| **制冷耦合一致性** | 用 §5.2 各 $u_2$ 档位的联合阶跃数据，检查线性模型预测的静态增益 vs 实测 | 标称工作区（增益变化 <20%）内吻合；超出该区则限制工作区或改用 §2.9 方案 3 |
| **路径②（仅风扇制冷）一致性** | 用 §5.2 纯风扇阶跃（$u_1=0$）数据做自由仿真，检查能否复现降温曲线与稳态下限 | 降温幅度误差 <20%；且仿真稳态值**不得**显著低于实测可达下限 $T_{wb}$——若模型声称"只开风扇能降到 $T_{wb}$ 以下"，说明 $g_{2y}$ 饱和项被漏掉，低温段会超温（§8 第 11 条） |
| 功耗模型 | 测试集 $R^2$ | > 0.95 |

**为什么必须看自由仿真误差**：MPC 用的是**多步递归预测**，一步预测误差会严重低估模型误差（脚本实测：一步 4.9% vs 自由仿真 14.6%）。用一步误差验收会得出"模型很好"的错误结论，上线后预测误差随时域放大、约束失效。

## 6 在线闭环实时运行流程

```
读取 k 时刻数据      时间戳对齐      ESO 状态更新      稳态目标+EMPC     指令下发
y_w,k              age 重建       估计 ŷ_true,k     最小化功耗        联锁检查
u1,k u2,k P_k       缺测插值       与 d̂_k, ΔT̂_k     + 温度约束       下发第一个
m_k(室温/冷却水)                                        + 终端余量       u1,k+1 u2,k+1
    │                  │                │                  │                │
    └───────────────────────────────────────────────────────────────────────►
              等待 T_s 采样周期，进入下一采样时刻，重复上述流程
```

1. **数据采集**：读取 $y_{w,k},u_{1,k},u_{2,k},P_k,m_k$，并附带各自的 `age`；
2. **时间戳对齐与质量门控**：用 age 重建读数的真实时刻；age 超阈值按缺测处理**（该拍不执行测量更新，只做时间更新）**；`temp_new=0` 的重复值同样不触发测量更新——这是对变采样/随机延迟最干净的处理；
3. **ESO 状态估计**：先验预测 → 后验修正 → 输出 $\hat y_{true,k},\hat d_k,\widehat{\Delta T}_k$；
4. **稳态目标计算**（§4.0）；
5. **EMPC 滚动优化**：冻结 $\widehat{\Delta T}_k$，求解凸 QP（热启动）；
6. **下发前联锁**（§2.9）：若 $u_1>0$ 则强制 $u_2\ge u_{2,\min}$；风扇故障 / 转速为 0 时强制 $u_1=0$；
7. **指令下发**：仅执行优化序列**第一个控制量**，并记录为本拍的 $u_{k-1}$（供下一拍 $\Delta u$ 使用）；
8. **滚动迭代**：等待 $T_s$，进入下一时刻。

### 6.1 工程兜底（上线必备）

| 场景 | 处置 |
| --- | --- |
| **QP 不可行** | 回退上一拍控制量；连续 N 拍不可行 → 进入「最大制冷」模式（$u_1=u_{1,\max}$ **且** $u_2=u_{2,\max}$：两条路径都要拉满）并告警 |
| **$\varepsilon>0$ 持续** | 长期运行模式：代表物理不可行（热负载超出制冷能力）→ 告警 + 最大制冷，不要静默继续。**对比实验模式例外**（§11.5 第 9 条）：初始越限与注水跳变造成的 $\varepsilon>0$ 是预期的，只有"非事件、非初始的稳定段持续 $\varepsilon>0$"才告警 |
| **ESO 冷启动未收敛** | 前 $3\tau_p/T_s$ 拍切 **§11.3 规则基线**（零模型依赖、绝对鲁棒，优于"固定中等电流"），待 $\hat d_k$ 收敛后再切入 EMPC |
| **温度长时间缺测** | 只做时间更新；超过阈值（如 5 个周期）→ 切 **§11.3 规则基线** 并告警 |
| **注水/置换事件（§11.2）** | 时刻已知 → 按混合公式把 $\Delta y_e$ 注入 $\hat{\boldsymbol{x}}_p$（事件前馈）；倒水—加水—搅拌窗口内的读数按缺测处理，只做时间更新 |
| **模型未通过 §5.7 准入** | 先用 **§11.3 规则基线** 上线（它不需要任何模型），补齐 §5 实验后再切 EMPC |
| **风扇停转 / 转速异常** | **强制 $u_1=0$ 并告警**。无风时**路径①（TEC 冷量送不出）与路径②（无强迫对流/蒸发）同时断**，制冷能力归零；TEC 仍在耗电、$\Delta T$ 越拉越大、热端持续受热 → 必须切断 TEC，不允许"风扇坏了大电流硬顶" |
| **QP 解出 $u_1>0$ 但 $u_2<u_{2,\min}$** | 按 §4.2 第 7 条联锁：优先取 $u_1=0$；其次才考虑把 $u_2$ 抬到 $u_{2,\min}$ 后重解 |
| **QP 解出 $u_1=0$ 且 $u_2\ge u_{2,\min}$** | **正常**（纯风扇制冷，§2.1 路径②），往往是全局最省电的解 → 不告警、不干预、不得强制抬电流 |
| **手/自动切换** | 无扰切换：切换瞬间把当前实际 $u$ 写入 $u_{k-1}$，避免 $\Delta u$ 跳变 |
| **抗积分饱和** | $\Delta u$ 限幅已在约束内；另需对 $\hat d_k$ 设上下界，防止长时间大残差导致估计发散 |
| **安全硬限 / 饱和接管** | 在 MPC 之外独立设置「温度 > $T_{\max}$ 直取最大制冷（$u_1=u_{1,\max}$ 且 $u_2=u_{2,\max}$）」的硬保护，不依赖优化器。**在对比实验模式中它被提升为正式工作模式**：带滞环 $\Delta_h$ 退出、退出后 $\Delta u$ 以实际接管值为基准，详见 §11.4.2 |

## 7 调参指南

| 参数 | 作用 | 调节方向 |
| --- | --- | --- |
| 观测器带宽 $\omega_o$ / $Q_d$ | 扰动跟踪速度 | ↑ → 突变响应快但放大噪声；↓ → 平滑跟踪慢变负载。单测量下放大代价更大，以残差噪声放大倍数为硬约束 |
| $R$（测量噪声方差 $\sigma_w^2$） | 对水温测量的信任度 | 按探头实测方差设（量化 0.1℃ + 抖动 + 插值残差） |
| $\rho$ | 松弛惩罚 | 应取到使 $\varepsilon$ 实际恒为 0（不是"允许超温"的调节旋钮）。对比实验模式同样如此——超温段由 §11.4.2 的全功率接管负责，不需要在这里给超温定价 |
| $\delta$ | 终端余量 | $\ge3\sigma_{model}$，模型越差越大 |
| $\lambda_1,\lambda_2$ | 控制平滑 | ↑ → 动作平滑、硬件冲击小，但动态响应变慢 |
| $N_p$ | 预测时域 | $N_p T_s$ 应覆盖 60~80% 过渡过程（建议 $N_p T_s\ge1.5\tau_p$） |
| $N_c$ | 控制时域 | 一般取 $N_p/3\sim N_p/2$；注意 $i\ge N_c$ 时 $u$ 保持不变 |
| $T_{ref}$ | 期望水温 | 越接近 $T_{\max}$ 越省电，但鲁棒裕度越小；建议与 $T_{\max}$ 留 ≥2℃。**分水岭是 $T_{wb}$**：$T_{ref}>T_{wb}$ 时纯风扇即可达标（§2.1 路径②），边际成本极低；$T_{ref}<T_{wb}$ 必须投入 TEC，功耗陡增。因此把 $T_{ref}$ 定在 $T_{wb}$ 以上能省掉绝大部分电费 |
| $u_{2,\max}$ | 风扇电压上限 | 因路径②的能效比远高于 TEC（§2.2 命题 4），应设在噪声/硬件允许的上限，**不要**为"省风机电耗"而压低——压低它只会逼 EMPC 去开更贵的 TEC |

## 8 模型适用边界说明

1. **负载带宽假设**：热负载变化的带宽低于观测器带宽。热系统为慢动态热惯性系统，该假设成立；
2. **执行器动态**：本装置建立时间 8s < $T_s=15$s，按 §2.8 方案 A 处理。迁移至机房 CRAC 时必须走方案 B（补执行器惯性状态）；
3. **功耗模型**为数据拟合模型，仅在实验采集的工况范围内有效，大范围外推会引入误差；$R_{tec},S_{tec}$ 与装置绑定，不可跨装置移植；
4. **温度传感器**动态仅考虑一阶惯性，忽略高阶探头动态；探头必须完全浸没，否则室温经探头柄导热形成未建模通路；
5. **制冷量对 $u_1$ 可能非单调**（§2.2 命题 1）：线性状态空间模型的静态增益为常数符号，因此只在实测的单调段内成立。辨识后必须检查——若水温降幅随电流增大而回落，说明已越过转折点，须把 $u_{1,\max}$ 压到该点以下，或改用增益调度 / 分段线性。**转折点的位置由 §5.2 联合阶跃数据实测给出，不预设**；
6. **$u_1$/$u_2$ 在路径①上串联耦合、路径②又随状态饱和，故二者不是可加独立通道**（§2.3）：净制冷量只有 $Q_{net}(u_1,0;\cdot)=0$ 这一条零约束，另有 $Q_{fan}(u_2;y)$ 随 $y\to T_{wb}$ 饱和；$g_{12}$、$g_{2y}$ 两个交叉偏导一般非零，因此线性模型的静态增益是**工作点与状态双重相关**的。本方案只在标称工作点邻域（增益变化 <20%）内成立。**跨域外推会系统性偏**，且偏差方向是单向的：模型高估制冷能力 → 实际超温。这是本模型最需要守住的一条边界；
7. **风扇停转时制冷能力归零**：$u_2\approx0$ 时路径①与路径②**同时断**，$u_1$ 无论多大都不产生有效制冷（注意：这不代表"风扇自己不制冷"——恰恰相反，风扇是独立制冷路径，只是它停转后两条路一起没了）。该工况既不能靠模型预测（线性模型会认为加电流有用），也不能靠反馈纠正（会一路加到上限），只能靠 §6.1 的硬联锁切断；
8. **风扇惯性同时串在 $u_1$ 通道上**（§2.8）：$u_2$ 变化时 $u_1\to y$ 的极点随之移动，是增益漂移的又一来源；
9. **单测量通道的已知局限**：水温是唯一的 ESO 测量，且是慢通道。负载突变只能在温升开始后被感知，$\hat d_k$ 的识别速度受对象时间常数限制；同时传感器偏置 $b$ 与热负载 $d$ 在稳态不可区分（§3.4）。若日后抗突变性能不足，优先的补救手段是**引入一路快通道测量**（如冷端风口温度或热端排风温度）作为第二输出，届时把 ESO 扩展为多输出（$L$: $n\times1\to n\times p$）即可，其余流程不变；
10. **不设结露约束**：本场景为开放水杯，冷端结露不构成实际风险。迁移到封闭机柜 / 电子器件工况时必须重新引入送风露点约束，并配湿度传感器；
11. **路径②（仅风扇制冷）存在饱和下限 $T_{wb}$**（§2.1）：水温越接近 $T_{wb}$，同样风量的制冷量越小，而线性模型给的是常值增益，会在低温段**高估**风扇制冷 → 实际降温不足 → 超温。因此当 $T_{ref}$ 接近或低于 $T_{wb}$ 时必须依赖 TEC，且该工作区要重新标定（增益随 $y-T_{wb}$ 变化，属 §2.9 的跨域情形）。无湿度测点时无法直接测 $T_{wb}$，用 `env-temp` 代理会**低估**风扇能力——偏差方向安全（实际降得比预测更低），但若想充分利用这条通道，应补一路湿度/湿球测点。

## 10 迁移机房的一一对应

| 实验台（TEC+风扇+水杯） | 机房正式场景（CRAC+服务器） |
| --- | --- |
| TEC 电流 | 冷水阀开度 |
| 风扇电压 | CRAC 风机转速 |
| 水杯热惯性 | 服务器机柜热惯性 |
| 水温探头一阶滞后 | 机柜温度传感器滤波滞后 |
| **路径①：制冷必须经风扇传递（$u_1$/$u_2$ 串联耦合）** | **冷量必须经风机送到机柜（水阀开度 / 风机转速 同样是串联耦合）** —— 耦合机理完全一致，§2.9 的处理策略可直接复用 |
| **路径②：只开风扇也能降温（拉向湿球温度 $T_{wb}$）** | **只开风机也能降温**（强化机柜 ↔ 回风/环境换热）；室外低温时即为**免费制冷 free cooling**，是数据中心最省钱的一档 —— 经济优先级顺序完全同构，"先风机、后冷机"同样成立 |
| 突加热扰动（可突变/慢漂移） | 服务器 GPU/CPU 瞬时满载或负载漂移 |
| 功耗模型 | 空调机组功耗模型（压缩机 + 风机，含启停） |

迁移时**代码与模型结构需要改变**的部分，以及不变的部分：

1. **执行器惯性必须补**（§2.8 方案 B）——阀门行程、风机升速均为数十秒量级，远大于 $T_s$；
2. **压缩机启停是整数决策**——引入 0/1 变量与最小运行/停机时间约束后，问题从 QP 变为 **MIQP**，求解器与代码结构必然改变；
3. **维度从 SISO 变 MIMO**——多机柜 × 多 CRAC，状态维数与约束规模大幅上升，需分布式/分层 MPC；
4. **测量通道会从 1 路变多路**——机房每个机柜都有进/出风温度测点，天然是多输出辨识，ESO 需从单输出扩展为多输出（$L$ 由 $n\times1$ 变 $n\times p$）。这会显著改善可观测性；
5. **不变的部分**是建模方法论与流程：§5 的实验顺序、§5.7 的准入验证、§6.1 的兜底清单，以及 §2.9 处理串级耦合的思路。
6. **规则基线的对照实验方法论可直接迁移**（§11）：机房侧的"规则基线"就是现有 CRAC 的**出厂回风温度设定 + 压缩机启停逻辑 + 风机定速**这套人工规则。§11 的配对实验设计、终点温度/能耗双指标、以及"考核温度进约束、能耗进目标"的处理口径，换到机房后完全不变，只需把基线规则换成现场实际在用的那套。

## 11 规则基线与对比实验设计

### 11.0 为什么必须补这一节

前面的全部设计都是"把控制做对"，但**没有对照组就无法回答"值不值得做"**。规则基线在本方案里承担三个角色，缺一不可：

| 角色 | 说明 |
| --- | --- |
| **对照组** | 给出性能比较的基准：EMPC 是否真的更省电 / 更守约束 |
| **兜底控制器** | 模型未通过 §5.7 准入、ESO 未收敛、长时间缺测时的降级目标（§6.1）。它零模型依赖、绝对鲁棒 |
| **诊断工具** | 基线跑出来的 $(u_1,u_2,y)$ 轨迹本身就是一份"已知策略下的系统响应数据"，可反过来用于校验模型符号与量级（§11.6） |

> **基线的定位不是"陪跑"**。它大概率在"稳定性/实现成本"上胜出，算法必须靠"同约束下更省电"来证明自己。若实测节能率不显著，诚实结论是"本工况下算法价值不显著"，而不是把指标改到算法赢为止。

### 11.1 实验工况与时间轴

| 时刻 | 事件 | 水温 |
| --- | --- | --- |
| $t=0$ | 200 ml 凉水 + 100 ml 热水配成 **50℃**，$V=300$ ml | $y(0)=50$（**已越限**，见下） |
| 0–15 min | 无外加热源，降温 | 下降 |
| $t=15$ min | 倒出 100 ml → 加入 100 ml 热水（实测 $T_{hot}$），$V$ 仍 300 ml | **瞬时跳升** $\Delta y_e$ |
| 15–30 min | 降温 | 下降 |
| $t=30$ min | 倒出 50 ml → 加入 50 ml 热水，$V$ 仍 300 ml | **瞬时跳升** $\Delta y_e$ |
| 30–45 min | 降温 | 下降 |
| $t=45$ min | 终点，读取考核温度 | $y(45)$ |

**"水位一致"的真实理由**：杯内水的热容 $mc=4.186\,V$（J/K）正比于容积。倒出与加入**同体积**，则 $V\equiv300$ ml 全程不变 → 热容恒定 → 辨识得到的 $A_p,B_p$ 全程有效、两条实验可直接比较。若水位漂了，等价于对象参数变了，模型与对比同时失效。因此必须用带刻度的量筒，动作前后核对 $V=300\pm5$ ml。

**⚠ 越限段不做优化：直接全功率接管（本方案的处理口径）**

$t=0$ 的水温 50℃ 已越过上限，15 / 30 min 的注水跳变也可能把水温顶过 45℃。处理方式为：**$y>45$℃ 时不做任何优化，直接全功率运行；EMPC 只在 $y\le45$℃ 的带内工作。**

| 模式 | 触发 / 退出 | 下发值 |
| --- | --- | --- |
| **饱和接管** | $y>T_{\max}$ 触发 | $u_1=5$ A，$u_2=24$ V（额定最大值） |
| **带内优化** | 回落到 $y\le T_{\max}-\Delta_h$ 才退出接管 | EMPC 的 QP 解 |

$\Delta_h=0.3$℃ 是**退出滞环**，防止在 45℃ 边界上每拍在"全功率"与"QP 解"之间来回切换（那会让电源每 15 s 大幅阶跃，且 QP 反复被覆盖）。完整设计见 §11.4.2。

这样处理带来三个直接好处：

1. **越限段根本不需要模型**。50℃ 起始与注水跳变恰恰是模型最不可信的时段（大信号、未建模的混合过程），此时用"全功率"这种**模型无关的饱和控制**，比让 QP 在它算不准的区域里硬解要稳健得多；
2. **不需要给超温定价**。另一种做法是"把超温按时间计分、再把分数换算成 Wh 塞进目标函数"——那需要一整套标定（分值系数、兑换比、$\ell_1$ 软约束），且标错一点就会让优化器优化错东西。走接管路线后越限段压根不进优化器，这套标定整个不需要了；
3. **越限段两条算法的动作被强制相同**（都是 24 V/5 A）⇒ 越限时长主要由**硬件能力**决定，不再混进算法差异，比较更干净。

**越限情况仍然要记录和报告，只是不计分**：

$$
T_{over}=\int_0^{T_{end}}\mathbf 1\big[y(t)>T_{\max}\big]\,dt\ \ (\text{min}),\qquad
D_{over}=\int_0^{T_{end}}\big[y(t)-T_{\max}\big]^{+}\,dt\ \ (℃\cdot\text{min})
$$

离散口径（与 15 s 采样一致）：$T_{over}=\frac{T_s}{60}\sum_i\mathbf 1[y_i>T_{\max}]$，$D_{over}=\frac{T_s}{60}\sum_i[y_i-T_{\max}]^{+}$；并按成因拆分（初始 / evt1 / evt2 / 其它）用于归因。

**三条记录规则（两组必须完全一致）**

1. **用读数 $y_w$ 判定，不用 ESO 的 $\hat y_{true}$**。报告要的是客观事实；$\hat y_{true}$ 含模型，等于让被评方自己定义真值。把两组实验的 $y_w$ 按 age 重建的时间轴重采样到统一 15 s 网格后再判定；
2. **量化死区**：判据取 $y_w>45.0+\Delta_q$，$\Delta_q=0.1$℃（一个量化台阶），避免 0.1℃ 量化在边界抖动把 $T_{over}$ 无意义地刷大；
3. **接管动作要打时间戳并按 §5.2 回读校验**。否则"下发了全功率但没生效"会被误读成算法没能力。

> **一个待确认的细节**：接管值取**额定最大值 24 V/5 A**（与基线同档，保证越限段两组完全同口径）。但 §2.2 命题 1 指出制冷量对电流**非单调**，5 A 未必是真正的最大制冷点。若 §5.2 实测确认最大制冷点在别处，可把接管值换成实测最优组合——但那样越限段就不再是"两组相同"，必须在报告里说明。**默认 24 V/5 A；要改就显式声明。**

### 11.2 注水置换是「可解析的状态跳变」，不是负载扰动

这是本实验在建模上最关键的一点，也是最容易被做错的一点。

设 $t_e$ 时刻倒出并加入 $V_{add}$（体积相同）的热水 $T_{hot}$，杯内总容积 $V$ 不变，则混合后的瞬时水温为

$$
y^{+}=\frac{(V-V_{add})\,y^{-}+V_{add}\,T_{hot}}{V}
\;=\;y^{-}+\underbrace{\frac{V_{add}}{V}}_{\alpha}\big(T_{hot}-y^{-}\big)
\;=\;(1-\alpha)\,y^{-}+\alpha\,T_{hot}
$$

本实验 $\alpha=1/3$（15 min 处）与 $\alpha=1/6$（30 min 处）。

**为什么它不能被 ESO 的 $d$ 通道吸收**

$d_k$ 建模的是**输入等效的持续热负载**（§2.5，$d_{k+1}=d_k$）。而注水置换是**状态本身的一次瞬时跳变**：水温在几秒内抬高若干度，之后对象动态完全回到原样。若不做处理，ESO 只能靠残差慢慢把它解释成一个"正向热负载" $\hat d_k>0$，而该估计在跳变结束后仍要按 $Q_d$ 的速度慢慢衰减 → 控制器在事件后**持续过度制冷**，白白费电。这正是 §3.2 所述"单测量慢通道"最吃亏的一类扰动。

**正确做法：事件前馈（时刻已知 → 直接注入状态跳变）**

1. **注入方向**：黑盒状态向量没有物理意义，取最小范数解
   $$\hat{\boldsymbol{x}}_p \leftarrow \hat{\boldsymbol{x}}_p+\Delta y_e\,v,\qquad v=\frac{C_p^{\top}}{C_pC_p^{\top}}\ \ (\Rightarrow C_pv=1)$$
   一阶/FOPDT 模型下 $x$ 即 $y$，直接相加即可。**探头状态 $x_s$ 不跳**——探头读数连续变化，这一拍不能跟着跳，否则残差符号反了；
2. **$\Delta y_e$ 的计算**：$\Delta y_e=\alpha\,(T_{hot}-\hat y_{true})$，其中 $T_{hot}$ **必须实测**（保温壶 + 温度计，每次倒水前记录）。$T_{hot}$ 的未知部分才交给 ESO 的 $\hat d_k$ 吸收；
3. **事件窗口按缺测处理**：倒水—加水—**搅拌**期间（约 20~40 s，含 1~3 个采样周期）读数不可信，只做时间更新（§6 步骤 2）。加水后必须轻搅 5 s 使水温均匀，否则探头读数不代表水体平均温度，$\alpha$ 混合公式本身也不成立；
4. **事件时刻**：由实验脚本触发并记录时间戳（精度 ±5 s，即 1/3 拍，可接受）。人工操作时应由脚本按"确认"按钮打时间戳，不要用名义时刻。

**在预测时域内跨越事件（凸性不受影响）**

§11.5 的收缩时域会跨越 $t=900\,$s 与 $t=1800\,$s。此时在对应步注入

$$\hat y^{+}_{k+i}=(1-\alpha)\,\hat y_{k+i}+\alpha\,T_{hot}$$

注意这是关于预测状态的**仿射变换**（$\alpha$ 与 $T_{hot}$ 都是常数），代入线性预测模型后仍是线性的 → **QP 的凸性与结构完全不变**，不需要逐次线性化。这是本实验能把"已知扰动事件"完整纳入优化的原因。

### 11.3 规则基线（对照组）的定义与实现

给定规则（三档查表，输入为**实测水温**）：

| 条件（水温 $y_w$） | 风扇电压 $u_2$ | TEC 电流 $u_1$ |
| --- | --- | --- |
| $y_w>45$℃ | 24 V | 5 A |
| $35<y_w\le45$℃ | 20 V | 3 A |
| $y_w\le35$℃ | 0 V | 0 A |

实现时必须约定的四点（**都要写进报告，否则基线被悄悄美化或恶化**）：

1. **边界重叠**：原口径在 $y_w=45$ 处两档重叠（"$t\ge45$"与"$35\le t\le45$"）、在 $y_w=35$ 处同样重叠。约定取**高档**（45℃ 用 24 V/5 A，35℃ 用 20 V/3 A）——因为 45℃ 是安全上限，重叠处取更安全的一侧；
2. **防抖：滞环 + 最小驻留**。0.1℃ 量化 + 15 s 更新下，贴着 35/45 边界会每拍反复跳档，电源大幅阶跃。取**滞环 0.3℃ + 最小驻留 60 s**。这只会减少无效动作，不会削弱基线的控温能力（切换变少、动作更少），属对基线**有利**的工程处理，必须注明；
3. **测量通道**：基线用**原始读数 $y_w$**（与算法同享一条测量通道）。算法用 ESO 的 $\hat y_{true}$ 做相位补偿——这是模型带来的、算法应得的优势，不算作弊，但应在报告中写明；
4. **安全联锁照常生效**：风扇故障 → 强制 $u_1=0$（§6.1）、输出使能 `output_on` 校验（§5.2）对两组一视同仁。这些不改变标称行为，只防事故。

基线模块 `baseline_rule.py` 的接口应返回 $(u_1^{set},u_2^{set})$ 与**切换计数**、**各档驻留时长**，供 §11.8 的"动作量"指标使用。

### 11.4 考核口径：终端温度进约束，能耗进目标（核心）

给定判据是「45 min 时刻算法水温不能超过规则基线水温」。直接把它当目标去"尽量降温"会毁掉本方案的全部意义，必须按下面三条处理：

**(a) 纯经济目标在这个口径下必然"不及格"**

EMPC 的目标是最小化电耗，而最省电的做法是**尽量不制冷**。给定 $T_{\max}=45$℃，它的最优轨迹就是贴着 45℃ 跑，终点温度会落在 40℃ 量级；而基线在 $\le45$℃ 时仍用 20 V/3 A 继续压、$\le35$℃ 才停，终点可到 27℃ 量级。按"终点不超过基线"直接判，EMPC 输得很惨——**但这是目标函数与考核指标不一致，不是算法差**。

**(b) 正确做法：把考核温度转成约束**

$$\hat y_{true,\,k+N_k\mid k}\;\le\;T_{end}^{*}-\delta,\qquad T_{end}^{*}=\bar y_{base}$$

即：把基线实测的终点温度当作**终端不等式约束**上界，能耗继续留在目标里。于是 EMPC 的产出变成"**到达不劣于基线的终点，用了多少电**"——这才是本方案的价值主张，也是唯一能同时满足用户口径与经济性目标的写法。

**(c) 只比温度不比能耗，本实验就失去了意义**

若只考核终点温度，EMPC 会被逼到与基线同温甚至更低，此时它反而可能**更费电**（为了压到同样的温度，它可能选了与基线不同的 $(u_1,u_2)$ 组合但总电耗更高）。因此**必须同时报告能耗**，且节能率才是主结论。

### 11.4.1 判据（三档，越限只报告、不计分）

| 级别 | 指标 | 判据 |
| --- | --- | --- |
| **L0 越限**（诊断项） | $T_{over}$、$D_{over}$（§11.1） | **只报告**。越限段两组都被强制为 24 V/5 A，差异主要来自硬件能力，不作为胜负依据 |
| **L1 终点温度** | $y(45\text{ min})$ | $y_{algo}\le\bar y_{base}$（你的口径）——只有"达标 / 不达标" |
| **L2 能耗**（主结论） | 全程累计电耗 $E$ | **在等终点前提下**比较；$E_{algo}/E_{base}<1$ 才算胜出 |

> **为什么 L2 要加"等终点"前提**：若算法终点是 20℃、基线是 27℃，单看 L1 是"大胜"，但多降的 7℃ 是拿电换来的，直接比能耗不公平。取 $T_{end}^*=\bar y_{base}$ 后终端约束会在边界上生效，算法会自然贴着它跑，此时比能耗才是等终点的。

**胜负判定一句话**：L1 不达标直接判负；L1 达标后看 L2 的节能率；L0 只写进报告做归因。

### 11.4.2 双模切换：越限接管 + 带内优化（替代"给超温定价"）

既然越限段直接全功率、不做优化，结构就变成一个**带滞环的双模切换**：

$$
(u_1,u_2)=
\begin{cases}
(5\text{ A},\,24\text{ V}) & \text{【饱和接管】}\ \hat y_{true}>T_{\max}\ \ \text{或}\ \ y_w>T_{\max}+\Delta_q\\[4pt]
\text{QP 解} & \text{【带内优化】}\ \text{回落到}\ \le T_{\max}-\Delta_h\ \text{之后的带内段}
\end{cases}
$$

五个实现要点：

1. **触发用"或"，退出用"与"**。$\hat y_{true}$（超前，但可能算错）与 $y_w$（滞后，但客观）**任一**报越限就接管——宁可多接管一拍，不可漏接管一拍，这是安全方向。退出则要求**两者都**回落到 $T_{\max}-\Delta_h$ 以下才交回 QP；
2. **退出滞环 $\Delta_h=0.3$℃**。防止在 45℃ 边界上每拍切换。它与 §11.3 给基线加的滞环属同一类处理，两组口径要一致地报告；
3. **QP 里的 $\varepsilon$ 回归"纯数值可行性"**（§4.1 原设计，$\rho$ 取足够大）。越限段已由接管层兜底，目标函数里**不需要** $\ell_1$ 标定、也不需要给超温定价。$\varepsilon>0$ 只说明"按模型算带内已守不住"，紧接着接管层就会介入；
4. **接管拍不参与 $\Delta u$ 平滑项的累积**：退出接管后的第一拍，$\Delta u$ 以**实际下发值**（5 A / 24 V）为基准计算，而不是以上一拍的 QP 解为基准（§1 里 $u_{k-1}$ 本来就定义为实际下发值，这里只是强调别写错）。副作用是好的：$\Delta u$ 限幅会让退出过程**分几拍**从全功率回落到经济工作点，避免热冲击与电源阶跃，**不要**为了让 QP 自由而放宽限幅；
5. **接管拍也要走 §2.9 的风扇-TEC 联锁与 §5.2 的回读校验**。全功率档电流最大，恰恰是"写入成功但没生效"最容易被忽略、后果也最严重的一档。

> **与 §6.1 的关系**：§6.1 的"温度 $>T_{\max}$ → 最大制冷"这条保护本来就存在，本小节只是把它**提升为对比实验的正式工作模式**，并补上退出滞环与 $\Delta u$ 的衔接，不是另起一套。

> **一个保守性说明**：QP 里"预测不越限"的硬约束，隐含地等价于"避免触发接管"，方向上是对的（接管档一定比带内经济工作点费电）。但它**不知道接管档具体有多费电**，所以是保守近似——算法可能为了躲接管而多压一点温度，牺牲掉 §11.6.1 那部分"借换水免费排热"的收益。要榨干这部分收益才需要回到"给越限定价"的软约束方案；**默认不这么做**。

### 11.5 算法侧改造（仅对比实验模式）

1. **收缩时域**：$N_k=\big\lfloor (T_{end}-t_k)/T_s\big\rfloor$，$N_0=180$ 步（45 min）。$N_c=N_k$ 时约 540 个变量、800+ 约束，OSQP 仍在毫秒级；若实测求解 >1 s，改用 **move blocking**（前 8 步逐拍、其后每 4 步一块，约 100 个变量）；
2. **终端约束**：$\hat y_{k+N_k}\le T_{end}^{*}-\delta$，其中 $\delta\ge\max(3\sigma_{model},\,0.3$℃$)$（0.3℃ 是抗 0.1℃ 量化 + 抖动的下限）；
3. **事件前馈进预测**：时域跨过 $t_e$ 时按 §11.2 的仿射式注入，凸性不变；
4. **§4.0 在有限时域模式下不再作为终端约束**（改为终端温度），但保留其解作为 QP 的**热启动初值**；
5. **末端滑行会自动出现，不需要额外代码**：优化器看得到终点，若提前关机仍能满足终端约束，它就会关机——这正是下一节节能来源①；
6. **$T_{\min}$ 本实验取 5℃**（仅防过冷/结冰；开放水杯无结露风险，见 §4.2 第 5 条）；
7. **$T_{ref}$ 在本模式下不出现**（终端约束已取代它），不要把 §4.0 的 $T_{ref}$ 又塞回约束里，否则会把"达到基线终点"变成"达到设定值"，与考核口径脱节；
8. **越限拍不走 QP**：由 §11.4.2 的饱和接管直接下发 24 V / 5 A。QP 里的 $\varepsilon$ 维持"纯数值可行性"（$\rho$ 取足够大，§4.1 原设计），**不需要** $\ell_1$ 标定、不需要给超温定价；
9. **$\varepsilon>0$ 在本模式下是预期的，不得触发告警**：初始 50℃ 与两次注水跳变物理上必然产生越限，且该段由接管层负责。告警判据改为"**非事件、非初始的稳定段持续 $\varepsilon>0$**"；
10. **事件前的温度由优化器自行决定，不要手工写"提前预冷"**：§11.2 的 $y^{+}=(1-\alpha)y^{-}+\alpha T_{hot}$ 已在预测模型里；抬高 $y^{-}$ 省电（§11.6.1）但会拉高跳变峰值、触发接管（接管恰恰是最低效的一档），压低 $y^{-}$ 则相反。**这个权衡现在由"预测不越限"硬约束 + 纯能耗目标自动解算**，不需要、也不应该再手工加"事件前预冷"逻辑——手写只会覆盖解算结果，且方向未必对。

### 11.6 EMPC 相对规则基线的四个节能来源（可验证的机理）

这四条不是"理论上应该更好"的套话，每条都能在轨迹上直接看出来，因此也构成了**诊断工具**：若实测轨迹不呈现对应形态，说明模型或权重有问题。

| # | 节能来源 | 机理 | 应在轨迹上看到的形态 |
| --- | --- | --- | --- |
| ① | **末端滑行** | 优化器看得见终点，会提前把 $u$ 降到 0，靠残余温差与热惯性把最后几度"滑"下去 | 终点前 2~5 min 内 $(u_1,u_2)\to0$，而水温仍在下降 |
| ② | **冷量时序重排（让免费散热多干活）** | 自然散热 $\propto (y-T_{amb})$，水温越高免费冷量越大；TEC 的 $\Delta T$ 越小效率越高（§2.7）。因此**把主动冷量推迟到高温段**更省电 | 主动制冷集中在事件后与高温段，而不是"一进带内就猛压" |
| ③ | **事件前馈 + 借换水免费排热** | 知道 15/30 min 要换水：一方面不会在为注定被抬高的温度浪费冷量，另一方面**倒掉的是热水 ⇒ 事件前越热，这次换水顺带排掉的热量越多**（推导见 §11.6.1） | 事件前的水温**高于**基线同期的水温（基线按 20 V/3 A 一路压到 35℃ 就断电，白白把该免费排掉的热量自己用电压掉了） |
| ④ | **组合寻优** | 基线固定 24 V/5 A，可能已越过制冷量的最大值点（§2.2 命题 1）而落在低效侧；EMPC 在 $(u_1,u_2)$ 上连续寻优 | 稳态段出现 $u_1$ 明显小于 5 A 而 $u_2$ 接近上限的组合（§4.0 预期：风扇能效比远高于 TEC） |

**对照：基线的形态**是" $>45$ 就全功率猛降、$\le35$ 就断电"的方波，它不利用未来信息、不利用热惯性、不做组合寻优——这三点正是 §10 迁移到机房后同样成立的优势（基线在机房侧就是"定回风温度设定 + 定速风机 + 压缩机启停"）。

### 11.6.1 为什么"事件前保持高温"反而省电（反直觉，必经推导）

把一次注水事件前后的账算清楚。事件前水温 $y^{-}$，跳变后 $y^{+}=(1-\alpha)y^{-}+\alpha T_{hot}$，终点要求降到 $y_{end}$。全程需从水体移除的热量：

$$
Q_{rm}=mc\underbrace{(y^{-}_0-y^{-})}_{\text{事件前段}}+mc\underbrace{(y^{+}-y_{end})}_{\text{事件后段}}
=mc\Big[y^{-}_0-\alpha\,y^{-}+\alpha\,T_{hot}-y_{end}\Big]
$$

$$
\boxed{\ \frac{\partial Q_{rm}}{\partial y^{-}}=-\alpha\,mc<0\ }
$$

**结论：事件前的水温越高，全程累计需要移除的热量越少。** 机理很直白——注入的热量是固定的（同样的 $V_{add}$、同样的 $T_{hot}$），**倒出去的热量却随 $y^{-}$ 增大**：把热水倒掉就是一次免费排热。

这与 §11.6 ②（推迟制冷、多用免费自然散热）是同一个方向的叠加效益，而且比它更强：每把事件前温度抬高 $\Delta$℃，就能**白省** $\alpha\,mc\,\Delta$ 的热量。15 min 那次 $\alpha=1/3$、$mc=4.186\times300=1256$ J/K ⇒ 抬高 1℃ 省 **419 J**；抬高 5℃ 省 **2.1 kJ**（约相当于 40 W 运行 52 s 的电耗量级——当然实际节能取决于 COP）。

**但它会触发全功率接管**：$y^{-}$ 抬高 ⇒ $y^{+}$ 抬高 $(1-\alpha)\Delta$ ⇒ 一旦越过 45℃ 就进入 §11.4.2 的饱和接管（24 V / 5 A）。而接管档是额定最大值、且 5 A 很可能已过制冷量的峰值（§2.2 命题 1），**效率恰恰是最差的**。于是形成一对干净的权衡：

| 方向 | 省下的 | 付出的 |
| --- | --- | --- |
| 事件前**抬高** $y^{-}$ | 白嫖 $\alpha\,mc\,\Delta$ 的排热 + 高温段 COP 更高 | 跳变峰值升高 → 可能触发全功率接管 → 在最低效的档上耗电 |
| 事件前**压低** $y^{-}$ | 躲开接管，全程留在高效带内 | 热量全得自己用电压掉，总排热量变大 |

**这组权衡不需要人工裁决**：预测时域里有事件跳变（§11.2），QP 的"预测不越限"硬约束会自动把 $y^{-}$ 压到"刚好不触发接管"的临界点，而在带内再按能耗最小自由寻优。这正是 §11.5 第 10 条强调**不要再手写"事件前预冷"逻辑**的原因——硬约束 + 能耗目标已经把边界解出来了，手写只会覆盖它。

> **两个要注意的副作用**：
> (i) "避免越限"的硬约束**不知道接管档具体有多费电**（§11.4.2 末条），所以算法会偏保守地多压一点，牺牲掉一部分白嫖收益。要榨干它就得回到"给越限定价"的软约束方案，默认不这么做；
> (ii) 抬高 $y^{-}$ 还必须留出事件后 15 min 内降到 $T_{end}^*$ 的**能力裕度**——终端约束会自动管住，但若模型高估了制冷能力，实测就会不达标（§8 第 6 条的保守方向在这里正好是"少抬一点"）。

### 11.7 实验公平性控制（不做这些，结论不可信）

单次 45 min 实验的噪声（LoRa 丢包、age 抖动、热水温度不一致、环境漂移）足以掩盖 20% 级别的差异。必须：

1. **配对交替**：按 B–A–B–A–B–A 顺序各跑 ≥3 次（共 6×45 min），用配对差消除环境单向漂移；
2. **环境对照**：全程记录 `env-temp` 与 `shuitong-temp`。同一次配对内两组的环境均值差 >1℃ → 该配对作废；
3. **$T_{hot}$ 必须实测并记录**：用保温壶盛装，每次倒水前读数。两组 $T_{hot}$ 差 >2℃ → 该配对作废（扰动强度不可比）；
4. **水位核对**：动作前后 $V=300\pm5$ ml，超出即作废；
5. **同一套脚本与门控**：同一采样脚本、同一 age 阈值、同一缺测规则、同一搅拌手法；
6. **执行器回读校验**：两组都按 §5.2 回读（模式字、`output_on`、设定值），避免"写入成功但没生效"污染某一组的数据。

### 11.8 结果报告模板

**指标表**

| 指标 | 计算口径 | 备注 |
| --- | --- | --- |
| 终点温度 $y(45)$ | 取 **44~45 min（最后 4 拍）的均值**，同时报告单点值与标准差 | 单点比较受 0.1℃ 量化 + 抖动影响，$\Delta<0.5$℃ 应判为"无显著差异" |
| $t_{enter}$ | 首次进入 $\le45$℃ 的时刻 | 只作诊断（反映最大制冷能力） |
| 越限时长 $T_{over}$ | 全程 $y_w>45.1$℃ 的累计时间（min） | **只报告、不计分**（L0 诊断项）；按成因拆分（初始/evt1/evt2/其它） |
| 越限深度 $D_{over}$ | $\int[y_w-45]^{+}dt$（℃·min） | 同上，只作归因 |
| **接管占比** | 处于饱和接管的拍数 / 总拍数 | 用它核对 $T_{over}$ 是否被"下发全功率但没生效"污染（§11.1 规则 3） |
| 累计电耗 $E$ | $E=\sum P_k T_s/3600$（Wh） | 用实测 $P_k$，不要用模型值 |
| **节能率** | $1-E_{algo}/E_{base}$（等终点前提下） | **主结论** |
| 动作量 | 切换次数 + $\sum\lvert\Delta u_1\rvert,\sum\lvert\Delta u_2\rvert$ | 执行机构磨损；基线含滞环/最小驻留后应更少 |
| 系统级 COP | $Q_{rm}/(3600\,E)$，其中 $Q_{rm}=Q_{inj}+mc\big(y(0)-y(45)\big)$，$Q_{inj}=\sum 4.186\,V_{add}\,(T_{hot}-y^{-})$，$mc=4.186\,V$ | 含免费自然散热，对两组同口径，**奖励多用自然散热**，是对 §11.6 ②的直接度量 |

**常见误判清单**

| 误判 | 为什么错 |
| --- | --- |
| 只比终点温度、不比能耗 | 无法体现 EMPC 价值（§11.4 (c)），甚至会得出相反结论 |
| 把越限时长当成胜负依据 | 越限段两组都被强制为 24 V/5 A，差异主要来自硬件能力；L0 只作诊断（§11.4.1） |
| 用单点值比温度 | 0.1℃ 量化 + 15 s 抖动下 0.2℃ 的差异无意义；用末段均值 + 报告 $\sigma$ |
| 判越限时用 ESO 的 $\hat y_{true}$ | 含模型 ⇒ 让被评方自己定义真值；报告必须用重采样后的 $y_w$（§11.1 规则 1） |
| 两组用不同的量化死区 / 重采样网格 | $T_{over}$ 对死区极敏感（擦边抖动直接计拍），两组必须跑同一套 `bench_compare.py` |
| 接管拍不回读校验 | 全功率档电流最大，"下发成功但未生效"最容易被忽略、后果也最严重（§11.4.2 要点 5） |
| 退出接管时把 $u_{k-1}$ 取成上一拍的 QP 解 | $\Delta u$ 必须以**实际下发值**（5 A/24 V）为基准，否则增量算错、输出跳变（§11.4.2 要点 4） |
| 两组在相隔很久的不同时段跑 | 环境漂移会让结论失效；必须配对交替 + 环境对照 |
| 基线加了滞环/最小驻留却不说明 | 基线被美化（动作量指标失真），须在报告注明 |
| 算法终点显著低于基线就宣称"更好" | 多降的温度是拿电换来的；应按 §11.4.1 的**等终点**口径比节能率 |
| 不记录 $T_{hot}$ | 两次实验的扰动强度不可比，整轮作废 |
| 用模型算出的 $P$ 统计能耗 | 必须用实测功率；模型值会把功耗模型的误差直接算成节能 |

### 11.9 基线的第二个用途：兜底与降级

规则基线不需要任何模型、不需要辨识、不会发散，因此是 §6.1 各降级场景的**首选目标态**，而不是"随便给个中等电流"：

- 模型未通过 §5.7 准入 → 用基线上线，补齐 §5 实验后再切 EMPC；
- ESO 冷启动未收敛（前 $3\tau_p/T_s$ 拍）→ 用基线；
- 温度长时间缺测 / QP 连续不可行 → 切基线并告警。

这样切换的好处是：**降级态本身就是可接受的产品级控制效果**，不会因为有模型就"必须依赖模型"。

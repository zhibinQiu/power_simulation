## UI/专业性评估对话
- 用户让我评估"钢铁节能减碳数字孪生平台"的界面UI与工业软件差距。
- 我第一轮错误地用 Blender/3D建模 标尺去比 3D 渲染品质，被用户纠正：**"这不是3d建模软件，主要是数值仿真"**。
- 修正后改用 MATLAB/Aspen/COMSOL 数值仿真标尺重评。结论：架构基因好（声明式 JSON 图 + carbon_engine.RULES 注册表），真正差距在（1）数值引擎严谨性（经验标定系数，非物料/能量平衡闭环）；（2）求解/分析能力（无参数扫描/敏感性/优化/不确定性）；（3）可复现性与真实数据接入。
- 给的优先级：P0 物料/能量平衡闭环 + 参数扫描/导出；P1 运行日志/版本管理 + 真实数据接入(OPC-UA/MES)；P2 优化求解器+蒙特卡洛；P3 时序/多情景/误差带图表。
- 教训：评价此类平台应锁定其"核心能力"选对标物，3D 场景只是呈现层，只按清晰度评判。

## 数值引擎"经验标定 vs 物料平衡闭环"代码级澄清
- 用户追问"经验标定系数不是平衡闭环怎么理解"。我读了 carbon_engine.py / calculators.py / factors.py 后澄清：
- **碳侧是认真的**：calc_* 用 `carbon_in - carbon_to_steel = carbon_to_co2` 碳元素守恒 + 国标公式 `E=AD×EF=量×NCV×CC×44/12`，对齐 GB/T 32151.5 物料平衡法。README 也说"不可作合规报送依据"是数据口径问题，非公式问题。
- **真正经验化的地方（连接/转换处）**：
  - 默认电耗 `elec = hm*0.03 / steel*0.05` 等经验系数（calculators.py 多处）
  - 产率常数 `coke_out=coal*0.75`、`pellets*0.65`、`ore*0.95`
  - 高炉操作耦合 `_bf_effective_fuel` 的 `-150/-250/-90/-30` 灵敏度（代码自注"经验耦合，体现因果方向而非精确冶金模型"）
  - 技术修正百分比 `0.85/0.9/0.9` 捕集率
  - 能流固定 30% 有效能劈分 `STEEL_EFF_EFFICIENCY=0.30`
  - DEFAULT_PARAMS 刻意"标定到 1800–2200 kg/t 区间"
- **架构性短板**：工序松耦合、各自独立算后求和（不联立、无迭代、无残差）；桑基图靠补"product/固定碳"差额节点凑视觉守恒（build_sankey line 310-330）。
- 已画架构对比图（当前独立求和 vs Aspen 闭环联立求解）。可落地的最小改造：挑 高炉→转炉 一对，加输入流股建模+守恒求解让它自动驱动下游。
